# 구현 계획 (요약)

## 범위

1차 버전은 서울·수도권 전 노선(1~9호선, 수인분당선, 경의중앙선, 경춘선, 경강선, 서해선, 신분당선, 공항철도, 인천 1·2호선, 의정부경전철/용인경전철/우이신설선, 신림선, 김포골드라인, GTX-A)을 다루고, 부산/대구/광주/대전/열차 종류(KTX·SRT·ITX·무궁화호)는 데이터가 없는 "추후 지원" 상태로 화면에 노출만 한다.

## 단계

1. **프로젝트 확인** — 기존 파일(`claude-code-prompt.md`, `data-integration-rules.md`) 확인, 세션 중 사용자가 추가한 `data/서울수도권 역명 raw.csv`(공공데이터포털 국가철도공단/철도공사 자료로 확인) 발견 및 출처 확인 질의.
2. **스캐폴딩** — pnpm(corepack) + Rust(Homebrew) 툴체인 준비, Vite+React+TS(strict)+Tailwind v4+Tauri 2 프로젝트 생성.
3. **문서화** — `docs/data-integration-rules.md`(가이드 원문), `docs/data-model.md`(스키마 설계 근거), 이 문서.
4. **SQLite 스키마** (`scripts/db/schema.sql`) — Station/StationAlias/StationGroup/Line/LineAlias/StationLine/TrainService/StationService/DataSource/ImportBatch/ManualResolution + 화면용 region/scope_option 테이블.
5. **순수 함수 라이브러리** (`src/lib/normalize`, `src/lib/geo.ts`, `src/lib/color.ts`, `src/lib/merge`, `src/lib/search`) — 초성 추출/부분일치, 역명·노선명 정규화, 오타 유사일치, 좌표 거리, HEX 검증/명암비, 자동 병합 판정, 검색 점수·정렬. 모두 Vitest 단위 테스트로 검증.
6. **노선 색상** — 위키백과 문서를 브라우저 도구로 열람해 서울·수도권 노선 색상값을 `data/reference/rail-line-colors-source.json`에 옮겨 적고, `scripts/import/generate-line-colors.ts`가 이를 `data/reference/rail-line-colors.csv`로 변환하며 WCAG 명암비로 글자색을 계산. `scripts/validate/validate-line-colors.ts`로 검증.
7. **가져오기 파이프라인** (`scripts/import/run-import.ts`) — CP949 원본을 읽어 정규화 → 동명역 후보를 유니온-파인드로 묶되 좌표가 없어 자동 병합 조건을 기계적으로 만족하지 못하는 점을 사용자와 상의해 "잠정 병합 + 검수 리포트" 정책으로 처리 → SQLite와 검수 리포트(`station-resolution-review.csv`) 생성 → 프런트엔드용 정적 JSON(`public/korsub-dataset.json`)까지 내보냄.
8. **검증** (`scripts/validate/run-validate.ts`) — 외래키, ID 중복, 출처 누락, 검색 문자열 누락, overrides 참조 무결성, 색상 충돌, 원본 인코딩 손상 의심 문자 등을 검사.
9. **검색 엔진** (`src/lib/search/engine.ts`) — 토큰화 → 노선 번호/텍스트 토큰 분리 → AND 매칭 → 8단계 점수 → 5단계 동점 정렬.
10. **데스크톱 UI** — `ScopeSelector`/`LineSelector`/`SearchBox`(ARIA combobox) + Tauri `resolve_database_path` 커맨드 + `@tauri-apps/plugin-sql`로 오프라인 SQLite 접근. 브라우저 미리보기/Playwright는 같은 DB에서 만든 정적 JSON을 읽는 대체 경로를 쓴다.
11. **테스트/빌드** — Vitest 단위+통합+컴포넌트 테스트, Playwright e2e, `tsc -b`, `oxlint`, `vite build`, `tauri build`.

## 의도적으로 미룬 것

- 대구/광주/대전, 열차 종류별 정차역: 실제 데이터가 없어 화면에는 노출하되 비활성화.
- 좌표 기반 자동 병합의 실제 적용: 원본에 좌표가 없어 정책적으로 "잠정 병합"으로 대체(문서화됨).
- SRT 노선색: 위키백과 문서에서 명확한 근거를 찾지 못해 임의 값을 채우지 않고 제외.

## 확장 1: 부산 추가

사용자가 부산 역명 원본 3종(부산교통공사 도시철도, 국가철도공단 부산김해경전철, 국가철도공단 부산 동해선)을 추가로 올려 부산을 두 번째 AVAILABLE 지역으로 편입했다.

- **가져오기 파이프라인 일반화**: 단일 소스에 하드코딩되어 있던 `run-import.ts`를 `scripts/import/sources/*` 어댑터 배열 기반으로 리팩터링. 각 어댑터는 원본 형식(CSV/xlsx, 컬럼명)이 달라도 공통 `RawStationInput` 모양으로 변환해 돌려주면 나머지 파이프라인은 그대로 재사용된다.
- **지역 간 오탐 방지**: 기존 동명역 그룹핑 로직이 지역과 무관하게 이름만으로 잠정 병합하던 잠재적 버그를 발견해 수정 — 서로 다른 지역(예: 서울 "중앙" vs 부산 "중앙")은 `isSameOrAdjacentRegion` 검사를 먼저 거쳐 병합 후보에서 아예 제외한다. 서울 데이터만 있을 때는 지역이 하나뿐이라 드러나지 않았던 문제였다.
- **원본 결함 대응**: 부산교통공사 CSV의 "역번호"가 실제로는 유일하지 않음을 발견(209가 수영·광안 두 역에 중복) — 원본을 고치지 않고 내부 식별자는 일련번호로 새로 부여했고, 표시용 외부 코드 중복은 검증 스크립트 경고로만 남겼다.
- **환승역여부 활용**: 국가철도공단 xlsx 두 종에 있는 "환승역여부" 컬럼을 `officialTransferConfirmed` 신호로 반영해 규칙 7.2.3(공식 환승 확인) 경로를 실제로 탈 수 있게 했다(단, 양쪽 출처 모두 신호가 있어야 자동 병합 근거로 인정).
- **영문 별칭 검색**: 원본에 있던 영문 역명을 `StationAlias`(FOREIGN_NAME, 소문자 정규화)로 저장해 영문 검색도 되게 했다. 이 과정에서 `normalizeForCompare`가 영문을 소문자로 통일하도록 일반화했다(규칙 5.8).
- **노선 색상**: 위키백과 문서에서 부산 도시철도 1~4호선, 부산-김해 경전철, 동해선 색상 6건을 추가로 옮겨 적었다.

## 확장 2: 환승역 통합 표시

사용자가 실제 지하철 앱처럼 환승역은 한 행에 노선 배지 여러 개로 보여 달라고 요청했다 — 애초 요구사항(오금 → 3호선·5호선 두 행)과는 다른 방향이라 여기 명시적으로 기록한다.

- `src/lib/search/engine.ts`에 `searchGrouped()`를 추가했다. `search()`(StationLine 단위 채점·정렬)의 내부 로직을 공유하되, 정렬이 끝난 뒤 `station_id`로 묶어서 그룹 단위로 `limit`을 적용한다(먼저 10개로 자르면 환승역의 남은 노선이 잘릴 수 있어서 순서를 바꿨다).
- `SearchBox.tsx`가 `search()` 대신 `searchGrouped()`를 쓰도록 바꿔, 실제로 병합된(`station_id`가 같은) 결과만 한 행에 배지 여러 개로 보여준다.
- 병합 여부는 여전히 가져오기 단계의 자동/수동 판정이 결정하므로, **사용자가 확인해 준 동명이역(양평, 신촌)과 부산 동래역(동해선 쪽만 별개)을 `data/overrides/station-resolution.csv`에 `KEEP_SEPARATE`로 명시**했다 — 이게 없으면 좌표 없이는 이름만 같아도 잠정 병합되어 잘못 합쳐 보일 뻔했다.
- 이 작업 중 overrides 검증 로직의 버그도 함께 고쳤다: 병합되고 나면 `station` 테이블에는 그룹 대표 원본 ID 하나만 남는데, 검증 스크립트가 최종 DB만 보고 "overrides가 참조하는 원본 ID 없음"을 오탐으로 잡아내고 있었다. 이 검사를 가져오기 스크립트(원본 후보 전체를 아직 갖고 있는 시점)로 옮겨 해결했다.

## 확장 3: 이름이 다른 환승역, 화면 표시명 정리, 화면 표기 세부 조정

- **이름이 달라도 병합**: 4호선 "총신대입구역"과 7호선 "이수역"처럼 정규화 역명 자체가 다른 환승역은 애초에 동명역 그룹핑에 걸리지 않는다. `resolveDuplicateGroups`가 이름 그룹 순회와 별도로 `station-resolution.csv`의 모든 `MERGE` 쌍을 한 번 더 훑어 강제로 합치도록 고쳤다.
- **병합 근거를 실제로 구분**: 이전에는 병합된 그룹이면 무조건 `NAME_ONLY_PROVISIONAL`로 저장했다. 이제 각 쌍이 어떤 근거(override MERGE → `OFFICIAL_TRANSFER`, 좌표 → `COORDINATE`, 그 외 → `NAME_ONLY_PROVISIONAL`)로 합쳐졌는지 추적해, 그룹 안에서 가장 낮은 확신도를 그룹 전체의 `merge_basis`로 기록한다.
- **표시명 override**: `data/overrides/station-display-name.csv`(신규)로 병합된 역의 대표 이름을 사람이 직접 지정할 수 있게 했다 — "총신대입구(이수)"가 그 예. 괄호 안 이름은 `StationAlias`(SUB_NAME)로도 자동 저장되어 "이수"만으로도 검색된다.
- **인코딩 손상 복구**: "4?19민주묘지" 같은 '?' 문자를 제거해 "419민주묘지"로 정규화(`stripEncodingArtifacts`). 원본 파일은 그대로 둔다.
- **"역" 접미사 화면 표시 규칙**: 자동완성 목록·선택 시 입력창에는 "역"을 뗀 이름을 보여주되(`formatStationDisplayName`), "서울역"·"부산역"은 예외로 유지한다.

## 확장 4: 전국 역사고유번호 원본으로 통합, 대구·광주·대전 추가

사용자가 `RAIL_OPR_ISTT_CD/LN_CD/STIN_CD` 표준 코드 체계를 쓰는 전국 역사고유번호 원본(1,102행)을 추가하며, 이전 서울·부산 개별 원본을 전부 이 파일로 교체하고 대구·광주·대전까지 넣어 달라고 요청했다.

- **지역 분류 1단계**: `scripts/import/split-national-source.ts`가 원본을 읽어 `(RAIL_OPR_ISTT_CD, LN_CD)` 조합을 내부 `line_code`로 매핑하고(`nationalLineDefinitions.ts`의 `OPERATOR_LINE_TO_CODE`), 지역별로 `data/normalized/*.csv` 5개를 만든다. 인천공항 자기부상철도(6개 역)는 사용자 확인에 따라 여기서 제외한다.
- **구간별 운영기관 통합**: 같은 번호의 노선이 구간마다 운영기관이 갈리는 경우(1호선=서울교통공사+한국철도공사, 4호선=+남양주도시공사, 8호선=+구리도시공사, 7호선=+인천교통공사, 서해선=한국철도공사+서해철도)는 승객이 환승 없이 잇는 하나의 노선이므로 같은 `line_code`로 합쳤다. `LN_CD` 값 자체("1","2","3"...)는 도시마다 재사용되므로 지역까지 함께 봐야 한다는 점을 확인했다.
- **아키텍처 정리**: `seoulMetro.ts`/`busanMetro.ts`/`busanGimhaeLrt.ts`/`busanDonghae.ts` 4개 어댑터를 지우고, 지역 5곳이 재사용하는 로더 하나(`nationalRegionSource.ts`)로 교체했다. `data_source`는 물리적으로 같은 파일이라도 지역별로 별도 `source_id`를 부여해 추적한다.
- **기존 검수 결정 재적용**: 신촌·양평 `KEEP_SEPARATE`, 부산 동래 `MERGE`+`KEEP_SEPARATE`, 총신대입구/이수 `MERGE`를 새 `source_record_id`(`{운영기관}-{노선}-{역코드}` 형식)로 다시 매핑했다. 흥미롭게도 이 새 원본에는 총신대입구/이수가 이미 "총신대입구(이수)"로, 군자가 "군자(능동)"로 통합 표기되어 있어 사람이 확인해 둔 판단과 원본 데이터가 서로 검증해 주는 모양이 됐다.
- **부역명 처리 재확인**: "경성대.부경대(동명대학교)"처럼 가운데점+괄호가 섞인 표기, "봉황(김해여객터미널)"처럼 이전에 사용자가 다른 원본에서 지웠던 괄호 부역명도 기존 정규화 파이프라인(괄호 분리, 문장부호 비교용 제거)이 그대로 처리했다 — 별도 로직을 추가하지 않았다.
- **노선 색상**: 대구 1~3호선, 대경선, 광주 1호선, 대전 1호선 색상 6건을 위키백과에서 추가로 확인해 옮겨 적었다.
- **의도적으로 미룬 것**: 이 원본에는 영문 역명·주소·환승역여부 컬럼이 없어 부산 역들의 영문 별칭이 빠졌다(사용자 확인). 대경선은 대구·경북에 걸쳐 있지만 별도 "경북" 범위가 없어 잠정적으로 "대구"에 포함했다(동해선을 "부산"에 포함한 것과 같은 방식).

## 확장 5: 부역명 검색 제외, "역" 접미사 예외 확대

사용자가 대경선은 대구로 유지하고, 영문 검색은 애초에 불필요하며(변경 없음), 괄호 안 부역명은 검색에서는 빠지도록, "역" 접미사 예외를 서울역·부산역 외 대구역·동대구역·대전역까지 확인해 달라고 요청했다.

- **부역명 검색 제외**: 확장 3에서 도입했던 부역명 → `StationAlias`(SUB_NAME) 자동 저장을 되돌렸다. `run-import.ts`는 이제 `naming.subName`을 `station.sub_name` 컬럼에만 저장하고 별도 별칭 행은 만들지 않는다 — 즉 "봉황(김해여객터미널)"은 화면에는 그대로 보이지만 "김해여객터미널"만 쳐서는 더 이상 검색되지 않는다. "이수"(총신대입구(이수))도 마찬가지.
- **"역" 접미사 예외 확대**: `SUFFIX_DISPLAY_EXCEPTIONS`(`src/lib/displayName.ts`)를 `서울역·부산역` 2개에서 `서울역·부산역·대구역·동대구역·대전역` 5개로 늘렸다. DB의 `official_name`을 직접 확인해 5곳 모두 "역" 접미사가 원본에 살아있음을 검증했다.
- **대경선 지역 소속**: 별도 조정 없이 확장 4의 결정(대구 소속)을 그대로 유지.

## 확장 6: "이 노선의 역 보기" (노선 내 역 순서 목록)

사용자가 범위+노선을 고른 뒤 그 노선에 속한 역 전체를 볼 수 있는 버튼을 요청했다 — 정렬 기준은 "로우데이터의 STIN_CD 기준으로".

- **원본 순서 확보**: `scripts/import/sources/nationalRegionSource.ts`가 그동안 버리고 있던 `station_code_raw`(STIN_CD)를 `RawStationInput.sourceStationCode`로 실어 나르도록 고쳤다. 원래 `station_line.sequence` 컬럼은 스키마에 있었지만 한 번도 채운 적이 없었다(항상 NULL).
- **자연 정렬 비교자**: `src/lib/normalize/stationCode.ts`(`compareStationCode`)를 새로 만들었다. STIN_CD 표기가 노선마다 달라("100", "0115", "S07", "100-1" 같은 지선 표기까지) 단순 문자열 비교로는 순서가 어긋나, 숫자로 이어진 구간은 숫자값으로 비교하는 자연 정렬(natural sort)을 썼다.
- **가져오기 파이프라인**: `run-import.ts`가 `station_line` 삽입 직전에 후보를 `line_id` 단위로 묶어 `compareStationCode`로 정렬하고, 1부터 시작하는 순번을 `sequence` 컬럼에 채운다.
- **조회/검색 레이어**: `queries.ts`(`STATION_LINE_QUERY`)·`mapRowsToRecords.ts`·`StationLineRecord`(`src/lib/search/types.ts`)에 `sequence` 필드를 추가해 SQLite(Tauri)와 정적 JSON(브라우저) 양쪽에 동일하게 흘러가게 했다.
- **순수 함수**: `src/lib/search/engine.ts`에 `listStationsOnLine(candidates, lineId)`를 추가했다. `sequence` 순으로 정렬하고, 환승역이면 그 역에서 갈아탈 수 있는 다른 노선들(`transferLines`)도 함께 계산해 반환한다(이미 있는 `station_id` 병합/환승 판정을 그대로 재사용한다).
- **UI**: `src/components/LineStationsPanel.tsx`(신규) — 노선 선택 아래에 "이 노선의 역 보기" 버튼을 두고, 펼치면 순번·역명·환승 노선 배지를 나열한다. `App.tsx`가 `selectedLineId`가 실제로 선택돼 있을 때만("전체 노선"이 아닐 때) 렌더링한다.
- **데이터 결함 발견 및 수동 보정**: 검증해 보니 1호선(코드 150~159)과 3호선(코드 309~318) 두 노선은 서로 다른 두 운영기관이 같은 코드 구간을 완전히 다른 실제 구간(예: 1호선 — 서울교통공사의 "서울역~동묘앞" 도심 구간 vs 한국철도공사의 "송내~도원" 경인선 구간)에 독립적으로 매겨 놓았다 — 그 구간만 실제 노선도 순서와 다르게 보였다. 이미 있던 `run-validate.ts`의 "같은 노선 내 외부 코드 중복" 경고가 정확히 이 문제를 잡아냈다(이전에는 `sequence`를 채운 적이 없어 이 경고가 한 번도 실제로 뜬 적이 없었다). 처음엔 자동으로 짐작해 바로잡지 않고 README에 알려진 한계로만 남겼는데, 사용자가 수동 보정을 요청해 `data/overrides/station-line-sequence.csv`(신규)를 추가했다 — 해당 20개 역(source_record_id 기준)에 정렬 전용 키(예: 1호선 서울교통공사 구간은 `123.01`~`123.10`, 회기(123)와 남영(134) 사이에 정확히 끼워 넣는 값)를 사람이 직접 지정하고, `run-import.ts`가 `sequence` 계산 시 이 키가 있으면 `source_station_code` 대신 그 키로 정렬한다. 원본 `source_station_code` 컬럼 자체는 그대로 두고(그래서 위 검증 경고는 여전히 뜨며, 문구만 "화면 표시 순서는 override로 바로잡음"으로 보강했다), 정렬에만 영향을 준다.

## 확장 7: 데이터 정확도 보정 4건 (사용자 검수)

사용자가 실제 데이터를 확인하며 네 가지를 지적했다.

- **부역명 화면 표시 규칙 재정리**: 확장 3~5까지는 괄호 안 부역명을 화면에 항상 남겼는데(검색에서만 제외), 사용자가 "쌍용(나사렛대)"·"총신대입구(이수)" 두 역만 예외로 남기고 그 외 전국 역은 화면에서도 부역명을 떼라고 요청했다. `src/lib/displayName.ts`의 `formatStationDisplayName()`에 `SUB_NAME_DISPLAY_EXCEPTIONS` 허용목록을 추가하고, 그 외에는 `splitParenthetical()`로 부역명을 뗀 본 역명에 "역" 접미사 규칙을 적용한다(예: "봉황(김해여객터미널)역" → "봉황"). DB의 `sub_name` 컬럼 자체는 안 건드렸다 — 순수 화면 표시 함수만 바꿨다.
- **역명 변경 반영**: 용인 에버라인 "운동장.송담대"(source_record_id `EV-E1-Y120`)가 실제로 "용인중앙시장"으로 개명됐다는 확인을 받아 `data/overrides/station-display-name.csv`에 등록했다(기존에 만들어 둔 override 메커니즘을 그대로 재사용).
- **잘못된 환승 판정 정정**: 부산 1호선·동해선의 "좌천"·"부전"이 이름은 같지만 실제 환승역이 아니라는 확인을 받아, 동래역(확장 2에서 이미 처리한 패턴)과 똑같이 `data/overrides/station-resolution.csv`에 `KEEP_SEPARATE` 두 쌍(`BS-1-116`↔`KR-K6-K125`, `BS-1-120`↔`KR-K6-K110`)을 추가했다 — 재가져오기 후 두 역 모두 station_group이 풀리고 서로 다른 station_id로 분리됐다(station 940→942, merged_group 137→135).
- **"역" 접미사 예외 추가**: 대경선 "서대구역"이 화면에서 "서대구"로 접미사가 떨어져 보이는 게 어색하다는 지적을 받아 `SUFFIX_DISPLAY_EXCEPTIONS`에 추가했다(서울역·부산역·대구역·동대구역·대전역과 같은 패턴).

## 확장 8: KTX 추가 (첫 열차 종류·첫 cross-region 환승)

사용자가 `한국철도공사_KTX 노선별 역정보_20251121.csv`를 새 출처로 추가하며, 참고 사이트([metrotyping.kr](https://metrotyping.kr))의 노선 분류·색상을 따르고, 기존 지하철·전철역과 이름이 같은 KTX역은 환승으로 합치되 "역" 접미사가 원본에 없는 점을 감안해 달라고 요청했다. TRAIN_SERVICE 범위가 처음으로 실제 데이터를 갖게 된 사례다.

- **새 출처 어댑터**: `scripts/import/sources/ktxSource.ts` — 이 CSV는 1행이 진짜 헤더가 아니라 파일명을 옮겨 적은 제목 줄이라 건너뛴다. `노선명`(경부선 등)으로 노선을, `순번`으로 노선 안 물리적 순서를 그대로 준다 — 원본 코드가 운영기관별로 겹치는 1호선/3호선과 달리 여기는 자연 정렬만으로 충분하다.
- **노선 정의**: `scripts/import/sources/ktxLineDefinitions.ts` — 경부선/호남선/전라선/강릉선/중앙선/경전선/중부내륙선 7개. 배지 표시명은 "KTX-경부"처럼 "KTX-" 접두사 + 노선명(선 생략)으로 통일했다(사용자 확인, 앞으로 추가할 열차 종류도 같은 형식을 따른다).
- **KTX 전용 pseudo-region**: KTX는 특정 도시 지역이 아니라 전국을 가로지른다. `station`/`line` 테이블의 `region_code`가 NOT NULL로 `region` 테이블을 참조하는 기존 스키마를 그대로 살리기 위해, 도시 지역 5개와 나란히 `region_code="KTX"`를 하나 더 두었다(`region`/`train_service`/`scope_option` 세 테이블 모두 갱신, `train_service.status`도 KTX만 AVAILABLE로 바꿨다). 화면의 "운행 범위 선택" 그리드는 그대로 재사용된다 — REGION과 TRAIN_SERVICE가 이미 같은 그리드에 kind로만 구분되어 있었기 때문이다.
- **cross-region 환승**: KTX 역 25개가 이름이 같은 기존 역(서울/부산/대전/동대구/서대구/광명/수원/영등포/행신/용산/청량리/상봉/덕소/양평/판교/부발/경산/구포/광주송정/기장/남창/센텀/신해운대/태화강/부전, 그리고 마산은 제외)과 실제로 같은 역사를 공용한다. `resolveDuplicateGroups`의 자동/잠정 병합은 `isSameOrAdjacentRegion`이 지역이 다르면 애초에 후보로 보지 않으므로(KTX region_code가 도시 지역과 다르다), 총신대입구/이수 때처럼 `data/overrides/station-resolution.csv`에 `MERGE`를 사람이 직접 25건 명시했다. 반대로 이름은 같지만 실제로는 다른 역(KTX "마산"(창원) vs 김포골드라인 "마산역"(김포), KTX "용산"(서울) vs 대구 2호선 "용산(서부법원.검찰청입구)역", KTX "부전" vs 부산 1호선 "부전(부산시민공원.송상현광장)역")은 `KEEP_SEPARATE`로 명시해 이름만 보고 오판하지 않게 했다 — 정확한 대상을 짚기 위해 원본 STIN_CD/순번 기반 `source_record_id`를 하나하나 확인했다(예: 부산 1호선·동해선 둘 다 "부전"이 있어, KTX 중앙선의 부전이 실제로는 동해선 쪽과 같은 역이라는 걸 좌표 없이 노선 이름과 실제 지리 지식으로 판단해야 했다).
- **범위 필터링을 station.regionCode → line.regionCode로 전환**: KTX 이전에는 한 역의 모든 노선이 항상 같은 지역이라 `station.regionCode`로 걸러도 결과가 같았다. 서울역처럼 "도시 지역 노선 + KTX 노선"이 한 역에서 만나는 순간 이 가정이 깨진다 — station은 병합 대표(예: SEOUL_METRO)의 지역 하나만 갖지만, 그 역에 딸린 개별 `station_line`(예: "KTX-경부")은 자기 노선의 범위(KTX)를 그대로 유지해야 하기 때문이다. `App.tsx`의 `candidatesForScope`와 (쓰이진 않지만 일관성을 위해) `deriveLinesForRegion`/`loadStationLinesByRegion`을 모두 `record.line.regionCode` 기준으로 고쳤다. 이 변경 전에는 "KTX" 범위를 고르고 "서울"을 검색하면 결과가 0건이었다(station.regionCode가 SEOUL_METRO라 KTX 필터에 안 걸림) — 실제로 이 버그를 먼저 재현해 확인한 뒤 고쳤다.
- **노선 색상 출처 구조 변경**: `data/reference/rail-line-colors-source.json`이 그동안 출처 하나(위키백과)만 가정한 구조였다(`source` 단일 객체를 모든 entry가 공유). KTX 색상은 사용자가 지정한 다른 사이트(metrotyping.kr)에서 왔으므로, `sources`(배열) + 각 entry의 `source_id` 참조 구조로 바꿨다(기존 40개 entry는 전부 `wikipedia-rail-line-colors`로 마이그레이션). `scripts/import/generate-line-colors.ts`도 이 구조에 맞게 고쳤다. KTX 색상 값 자체는 브라우저로 metrotyping.kr에 접속해 각 노선 배지의 실제 CSS `background-color`(`getComputedStyle`)를 읽어 그대로 옮겨 적었다 — 기존에 있던 임시 자리표시자 `KR-KTX`(단일 회색조 색상, "추후 지원" 메모)는 이제 실제 노선별 색상 7개로 대체되어 지웠다.

## 확장 9: 다중 배지 목록 — 원형 아이콘으로 교체

사용자가 "이 노선의 역 보기" 목록에서 환승 노선이 많은 역(특히 KTX 도입 이후, 예: KTX-호남 노선의 서울역은 5개 노선이 겹친다)의 배지 줄이 너무 길어져 줄바꿈이 지저분해지는 문제를 스크린샷으로 보여줬다. 참고 사이트(metrotyping.kr)의 노선 선택 화면(원 안에 짧은 글자만 넣는 아이콘)을 그대로 따라 달라고 요청했다.

- **`icon_label` 컬럼 추가**: `line` 테이블에 `icon_label TEXT NOT NULL`을 추가했다. 참고 사이트 스크린샷을 그대로 옮겨 43개 노선 전부에 짧은 아이콘 글자를 매겼다 — 숫자 노선은 숫자만("1"), 지역 접두사가 있는 노선은 지역+번호("부1", "대2", "인1"), 이름이 있는 노선은 앞 두 글자("경의", "공항", "동해"), KTX는 7개 노선 전부 "KTX"로 통일(참고 사이트도 노선별로 색만 다르고 아이콘 글자는 같다 — 어느 노선인지는 색과 전체 이름(title/aria-label)으로 구분한다).
- **`LineIconBadge` 컴포넌트(신규)**: 원형 배지, 안에 `icon_label`만 표시하고 전체 이름은 `title`+`aria-label`(`role="img"`)로 접근성 확보. 기존 `LineBadge`(알약 모양, 전체 이름 표시)는 없애지 않고 배지가 하나뿐인 곳(노선 선택 버튼, "이 노선의 역 보기" 패널 상단의 "현재 노선" 표시)에는 그대로 둔다 — 문제는 "여러 배지가 한 줄에 나열되는" 곳에서만 있었다.
- **적용 범위**: `LineStationsPanel.tsx`의 환승 노선 배지, `SearchBox.tsx`의 환승역 그룹 배지. 두 곳 다 한 역에 여러 노선이 붙을 수 있는 자리라 같은 문제가 있었다.
- **테스트 갱신**: 배지 텍스트를 직접 찾던 테스트들(`getByText('3호선')` 등)을 접근성 라벨 기준(`getByRole('img', { name: '3호선' })`)으로 바꿨다 — 아이콘 글자가 줄어들어도(예: "3호선" → "3") 테스트가 실제 의도(그 노선 배지가 있는지)를 그대로 검증하게 됐다.

## 확장 10: KTX 동해선 추가(원본 갱신), SRT 메뉴 제거

사용자가 KTX 원본 파일을 갱신해 동해선(18개 역)이 새로 생겼다는 걸 알려주며 반영을 요청했고, 이어서 SRT 메뉴 자체를 지워 달라고 했다.

- **동해선 반영**: `scripts/import/sources/ktxLineDefinitions.ts`에 8번째 KTX 노선(`KTX-DONGHAE`, 표시명 "KTX-동해")을 추가했다. sortOrder는 참고 사이트(metrotyping.kr)의 그리드 순서(경부→호남→전라→강릉→중앙→동해→경전→중부내륙)를 그대로 따라 중앙선 다음·경전선 앞에 끼워 넣었다(경전선·중부내륙선의 sortOrder를 하나씩 밀었다). 색상은 이전 세션에서 metrotyping.kr을 브라우저로 열어 이미 캡처해 둔 값(`rgb(38,112,184)` = `#2670B8`, "동해선"·"동해선 전구간" 배지가 공유하는 색)을 그대로 썼다 — `data/reference/rail-line-colors-source.json`에 `KTX-DONGHAE` entry 추가.
- **새 override 없이 자동으로 이어진 환승**: 동해선의 서울/광명/천안아산/오송/대전/김천(구미)/동대구/경주/포항/부전/태화강은 기존 KTX 다른 노선에 이미 있던 이름이라 "같은 region(KTX) + 같은 역명" 자동 병합(byName pass)만으로 기존 그룹에 합류했고, 그 그룹이 이미 갖고 있던 도시 지역 환승(예: 부전→동해선/BUSAN, 서울→서울역/SEOUL_METRO)에도 транзит적으로 이어졌다 — `data/overrides/station-resolution.csv`를 전혀 건드리지 않았다. 강릉/정동진/묵호/동해는 기존 KTX 강릉선과 자동 병합됐다. 영덕/울진/삼척은 완전히 새로운 이름이라 독립된 KTX 전용 역이 됐다. 재가져오기 전에 미리 각 이름을 기존 DB와 대조해 확인한 뒤 진행했다.
- **SRT 메뉴 제거**: `run-import.ts`의 `train_service`/`scope_option` 시드에서 SRT 행을 완전히 뺐다(추후 지원 COMING_SOON 후보에도 올리지 않음 — ITX/무궁화호와는 다르게 취급). `ScopeSelector`는 DB에서 읽은 `scope_option`만 그리므로 코드 변경 없이 자동으로 버튼이 사라졌다. e2e의 "추후 지원 비활성화" 테스트 대상을 SRT에서 ITX로 바꾸고, "SRT는 메뉴 자체가 없다" 테스트를 새로 추가했다.
- **문서 정정**: KTX 환승역 개수를 문서 여러 곳에 "26개"로 잘못 적어 뒀던 걸 실제 override 행 수(25개)에 맞춰 정정했다(README, 이 문서, `data/metadata/sources.json`).

## 확장 11: KTX/SRT 운행계통 기반 재구축, SRT 복원

사용자가 KTX 데이터를 실제 운행계통(패턴) 기준으로 다시 가공한 파일 5종(`stations.csv`, `patterns.csv`, `pattern_stops.csv`, `game_line_patterns.csv`, `game_line_stations.csv`)을 제공하며 갱신을 요청했고, 이어서 "2026-09-01부로 SRT가 KTX 브랜드에 통합됐지만 이 앱은 수서발/서울·용산발을 사용자가 구분할 수 있어야 한다"며 확장 10에서 뺐던 SRT를 복원해 달라고 요청했다.

- **파일 배치 오류 발견**: 사용자는 5개 파일이 모두 `data/raw/`에 있다고 했지만 실제로는 2개(`game_line_patterns.csv`, `game_line_stations.csv`)만 `~/Downloads/`에 있었고 나머지 3개는 찾지 못했다 — AskUserQuestion으로 확인해 정확한 경로(`data/raw/files/`)를 다시 안내받았다.
- **데이터 자체 검증에서 결함 3건 발견**(사용자가 "정합성 검증을 마쳤다"고 했지만): (1) `stations.csv`의 "진부"가 `game_line_stations.csv`의 "진부(오대산)"보다 오히려 옛 이름이었다(사용자 설명과 신구 관계가 반대) — AskUserQuestion으로 확인 후 `stations.csv`를 갱신. (2) "동해선"×SRT 마지막 역(포항, S085)의 stop_order가 9여야 하는데 1로 잘못 찍혀 있었다. (3) "동해선 전구간"×KTX는 패턴 P22(부전~강릉)만 반영되고 P05(서울~동대구~포항)는 빠져 있으며, "동해선 전구간"×SRT는 데이터 자체가 없었다 — AskUserQuestion으로 확인해 (2)만 로더에서 보정하고 (3)은 원본 그대로 두기로 확정했다.
- **완전 교체**: `scripts/import/sources/ktxSource.ts`/`ktxLineDefinitions.ts`(2026-09-07 세션에 만든 평면 CSV 기반)를 지우고 `ktxGameLineSource.ts`/`ktxGameLineDefinitions.ts`로 교체했다. 새 로더는 `game_line_stations.csv` 하나만 읽는다(patterns.csv/pattern_stops.csv/stations.csv/game_line_patterns.csv는 근거 자료로 `data/raw/ktx-game-lines/`에 함께 보관하되 파이프라인에서 직접 읽지 않는다). 옛 평면 CSV는 `data/raw/_archive/`로 옮겼다.
- **`line.train_service_code` 컬럼 신설**: KTX/SRT가 실제로 같은 물리적 역을 공유해서 같은 pseudo-region("KTX")을 쓰게 하되(자동 병합을 공짜로 얻으려고), 화면에서는 서로 다른 버튼으로 보여줘야 하는 문제를 풀기 위해 `line` 테이블에 `train_service_code`를 추가했다. `App.tsx`의 `candidatesForScope`가 `scope.trainServiceCode`가 있으면 그걸로, 없으면 기존대로 `line.regionCode`로 거르도록 바꿨다 — `scope_option`의 KTX/SRT 행은 `region_code='KTX'`(공유)와 `train_service_code`(KTX 또는 SRT, 구분)를 함께 채운다.
- **노선 9(KTX)+5(SRT) = 14개 재정의**: 기존 8개 KTX 노선은 line_code를 그대로 유지하고, 새로 "동해선 전구간"(`KTX-DONGHAE-FULL`)과 SRT 5개(`SRT-GYEONGBU/HONAM/JEOLLA/DONGHAE/GYEONGJEON`)를 추가했다. SRT 아이콘 글자는 "SRT"로, 색상은 metrotyping.kr의 "SRT" 지역 선택 화면(보라 계열, KTX와 다른 배색)을 새로 캡처해 반영했다.
- **override 전면 재작성**: `source_record_id` 체계가 `KTX-{노선명}-{순번}`에서 `GL-{game_line}-{origin_type}-{station_id}`로 바뀌어, 기존 KTX MERGE/KEEP_SEPARATE 28건을 전부 새 ID로 다시 매핑했다. SRT 전용 출발역(수서/동탄/평택지제)은 기존 3호선·수인분당선·GTX-A·1호선 역과 같은 역사라 MERGE 3건을 추가로 확인해 넣었다 — 그 외 SRT 역(천안아산·대전·동대구 등)은 이름이 같은 KTX 역과 자동 병합되어 override가 필요 없었다(신규 override 0건으로 처리됨, 확장 10의 동해선 추가 때와 같은 패턴).
- **테스트 전면 재작성**: "실제 데이터: KTX" describe 블록을 새 line_code/노선 14개 구조에 맞춰 다시 썼다. `ktxRecords`/`srtRecords` fixture를 `line.regionCode`가 아니라 `line.trainServiceCode`로 다시 정의했다(KTX/SRT가 이제 같은 region을 공유하므로 regionCode만으로는 구분이 안 된다).

## 확장 12: "이 노선의 역 보기"에서 범위 밖 환승도 보이게

사용자가 스크린샷으로 KTX 범위에서 "KTX-동해(전구간)" 역 목록을 열었을 때 부전·태화강 같은 환승역에 배지가 아예 안 붙는 걸 보여주며, 범위를 하나로 좁혀도 다른 범위의 환승은 계속 보이게 해 달라고 요청했다.

- **원인**: `LineStationsPanel`이 `App.tsx`로부터 `candidatesForScope`(현재 고른 범위로 이미 좁혀진 배열)를 받아 `listStationsOnLine()`에 그대로 넘기고 있었다. `listStationsOnLine()`의 환승 노선 계산(`otherLinesByStation`)은 자신에게 주어진 배열 안에서만 "이 역의 다른 노선"을 찾으므로, 범위 밖 노선(예: KTX 범위에서 부산 지하철 동해선, SRT)은 애초에 배열에 없어 배지가 빠졌다. "이 노선"의 역 목록 자체는 `line.lineId`로 특정되어 범위와 무관하게 항상 같으므로, 영향은 순전히 환승 배지 쪽에만 있었다.
- **수정**: `LineStationsPanel`의 prop을 `candidates`(범위로 좁힌 배열)에서 `allStationLines`(전체 station_line)로 바꾸고, `App.tsx`가 `candidatesForScope` 대신 `indexState.index.stationLines`(전체)를 넘기도록 고쳤다. `listStationsOnLine()` 자체는 순수 함수라 손대지 않았다 — 어떤 배열을 넘겨받느냐만 바뀐 것이다.
- **검증**: KTX 범위 → "KTX-동해(전구간)" 역 목록에서 부전·태화강이 부산 동해선(지하철) 배지를, 경주·포항이 SRT-경부/SRT-동해 배지를 함께 보여주는 걸 브라우저로 확인했다. e2e 테스트를 추가해 회귀를 막았다.

## 확장 13: 김천(구미)·울산(통도사) 부역명

사용자가 "KTX역인 김천역은 김천(구미) 역으로, 울산역은 울산(통도사)로 부역명 추가하기. 절대 삭제금지."라고 요청했다.

- **확인**: `game_line_stations.csv`에는 김천(S015)이 이미 모든 노선(경부선/동해선/경전선 × KTX/SRT)에서 "김천(구미)"로 정확히 들어 있었다 — 손댈 필요가 없었고, "절대 삭제금지" 요청대로 그대로 두었다. 반면 울산(S063)은 부역명 없이 "울산"만 있었다.
- **최소 침습 수정**: 원본 CSV나 `station-resolution.csv`를 건드리지 않고, `data/overrides/station-display-name.csv`에 `GL-경부선-KTX-S063,울산(통도사)역` 한 줄만 추가했다 — 병합 그룹 전체(KTX-경부 + SRT-경부)의 표시명이 override로만 바뀐다.
- **표시 레이어 버그 발견 및 수정**: DB/override는 맞았지만 `src/lib/displayName.ts`의 `formatStationDisplayName()`이 괄호 부역명을 기본적으로 떼는 규칙이라, `SUB_NAME_DISPLAY_EXCEPTIONS`에 없는 "김천(구미)역"·"울산(통도사)역"은 화면에 그냥 "김천"·"울산"으로 잘려 나올 뻔했다. 두 이름을 `SUB_NAME_DISPLAY_EXCEPTIONS`(기존 "쌍용(나사렛대)"·"총신대입구(이수)")에 추가해 화면에서도 부역명이 남도록 고쳤다.
- **검증**: `import-summary.json`/`validate` 재실행으로 구조(행/역/노선/병합 개수) 변화가 전혀 없음을 확인했고, DB에서 김천(구미)이 그대로임과 울산(통도사)이 새로 반영됨을 직접 조회로 확인했다. 브라우저로 KTX 범위에서 "울산" 검색 시 "울산(통도사)"로 표시되고, "통도사"만 검색하면 (부역명은 검색에서 제외된다는 기존 규칙대로) 결과가 없음을, "김천" 검색 시 "김천(구미)"가 그대로임을 확인했다. 단위 테스트를 추가했다.

## 확장 14: 검색 자동완성에도 범위 밖 환승 노선 배지 적용

사용자가 스크린샷으로 SRT 범위 → SRT-경부 노선을 고른 화면에서, "이 노선의 역 보기" 목록(확장 12에서 이미 고친 곳)은 오송·김천(구미) 같은 역에 KTX 배지까지 온전히 보여주는데, 바로 아래 검색 자동완성 드롭다운은 같은 역인데도 SRT 배지만 보여주는(KTX 배지가 빠진) 걸 보여주며 자동완성에도 똑같이 범위 밖 환승을 보이게 해 달라고 요청했다.

- **원인**: 확장 12는 `LineStationsPanel`(노선 역 목록)만 고쳤을 뿐, 검색 자동완성(`SearchBox` → `searchGrouped()`)은 여전히 `App.tsx`의 `candidatesForScope`(범위·노선으로 이미 좁혀진 배열) 하나만 받아 그 안에서만 "같은 역의 다른 노선"을 모으고 있었다 — 그래서 오송처럼 KTX 5개 + SRT 5개 노선을 모두 갖는 역도, SRT 범위에서 검색하면 SRT 노선만 배지로 나왔다.
- **수정**: `searchGrouped()`에 `allStationLines`(전체 station_line) 옵션을 추가했다. 검색 자체(어떤 역이 결과에 포함되는지, 순서·점수)는 지금까지처럼 `candidates`(범위·노선으로 좁힌 배열)만 보되, 결과로 뽑힌 역 각각의 노선 배지만 이 옵션이 주어지면 station_id가 같은 전체 노선으로 보강한다 — `listStationsOnLine()`의 `otherLinesByStation`과 같은 원칙이다. `SearchBox`가 이 옵션을 받는 `allStationLines` prop을 추가로 받고, `App.tsx`가 `indexState.index.stationLines`(전체)를 그대로 넘긴다. 옵션을 안 주면 기존 동작(범위 안 노선만 모음)이 그대로 유지되므로 기존 테스트는 손대지 않고 통과했다.
- **검증**: 단위 테스트(`searchGrouped`의 `allStationLines` 옵션 3건, `SearchBox`의 범위 밖 배지 1건)와 e2e 테스트(SRT-경부 범위에서 "오송" 검색 시 KTX 배지도 뜨는지)를 추가했다. 브라우저로 SRT → SRT-경부 → "ㅇㅅ" 검색을 재현해 오송·울산(통도사)·천안아산 모두 KTX+SRT 배지가 함께 나오는 걸 확인했다(수정 전에는 SRT 배지만 나왔다).

## 확장 15: 아산↔천안아산 병합(이름 비동기화) + 부역명 검색 허용

사용자가 두 가지를 요청했다: (1) "수도권 1호선 아산역은 KTX/SRT의 천안아산역과 같은 역이지만, 기차와 전철간의 역명은 달라. 역명은 동기화 하지 말고, 환승 정보만 공유하게 해줘." (2) "일부 역에 대해서 부역명을 존치하기로 했는데, 해당 부역명을 가지고도 역명 검색이 가능하게 하자."

### (1) 아산 ↔ 천안아산 — 병합하되 이름은 강제로 합치지 않음

- **문제**: 두 역은 실제로 같은 역사를 공용하는 환승역이지만, 지금까지 아무 병합 관계도 없어서(정규화 역명이 "아산" ↔ "천안아산"으로 서로 달라 자동 병합 후보에도 못 오름) 서로 환승 배지가 전혀 나오지 않았다. 게다가 기존 "병합 = 대표 이름 하나로 통일"이라는 구조를 그대로 병합에 적용하면, 둘 중 하나(예: "아산")가 대표가 되어 KTX 목록에서도 "아산"으로 보이는 등 실제로 다른 정식 명칭이 뭉개진다.
- **병합**: `data/overrides/station-resolution.csv`에 `MERGE,KR-1-P172,GL-경부선-KTX-S078` 한 줄을 추가했다 — 정규화 역명이 서로 달라도 사람이 확인한 환승역은 병합할 수 있는 기존 경로(`resolveDuplicateGroups`의 명시적 MERGE 처리)를 그대로 탄다.
- **이름 비동기화**: `station_line.display_station_name`(스키마에는 있었지만 화면에서 한 번도 쓰이지 않던 컬럼)의 기본값을 "병합 그룹의 대표 이름"에서 "원본이 원래 부르던 자기 이름"으로 되돌렸다 — 단, `station-display-name.csv`로 그룹 전체를 사람이 명시적으로 통일하기로 확정한 역(울산(통도사)·총신대입구(이수)·쌍용(나사렛대)·용인중앙시장)은 지금까지처럼 그룹 전체가 같은 이름을 쓴다(`run-import.ts`가 그룹별로 override 존재 여부를 기억해뒀다가 station_line마다 분기). `LineStationsPanel`·`SearchBox`(그룹 제목)를 `officialStationName`(대표 이름, 공유) 대신 `displayStationName`(노선별 자기 이름)을 쓰도록 바꿔 이 구분이 화면에 실제로 반영되게 했다.
- **양쪽 다 검색되게**: 병합 그룹은 `station.official_name` 하나만 갖는데다(대표는 "아산"이 됨 — 서울·수도권 소스가 KTX보다 먼저 읽혀서), 검색은 이 필드로 이름 완전/시작/부분일치를 판정한다. "천안아산"으로도 찾을 수 있도록, 대표 이름과 다른 원래 이름을 가진 구성원이 있으면 그 이름을 `station_alias`(MISC 타입)로 자동으로 남기게 했다 — 이 로직은 아산/천안아산 전용이 아니라 일반화돼 있어서, 부수적으로 "용인중앙시장역"(예전 이름 "운동장.송담대")도 옛 이름으로 찾을 수 있게 됐다(`docs/data-integration-rules.md` 6장이 원래 요구했던 "과거 명칭도 별칭으로 검색되게 한다"를 이제 실제로 지킨다).
- **검색 결과 제목이 검색어를 따라가게**: station_alias가 station_id 단위로 붙다 보니, "천안아산"으로 검색해도 같은 별칭을 공유하는 "아산"(1호선) 레코드가 동점으로 함께 걸려 정렬 순서에 따라 엉뚱하게 "아산"이 제목으로 나올 수 있었다. `evaluateAndSort()`의 정렬에 동점 처리 기준을 하나 추가했다 — 별칭으로 맞았다면, 그 별칭이 실제로 "자기 자신의"(`displayStationName`) 이름에서 왔는지를 우선한다. 이제 "천안아산"으로 검색하면 반드시 "천안아산"쪽 레코드가 앞선다.
- **검증**: 단위 테스트(`engine.test.ts`에 동점 처리 2건, `real-data-search.test.ts`에 아산/천안아산 통합 테스트 4건), e2e 테스트 1건을 추가했다. 브라우저로 "아산" 검색(제목 "아산" + KTX/SRT 10개 배지), "천안아산" 검색(제목 "천안아산" + 1호선 배지), 1호선 "이 노선의 역 보기"(98번 "아산") vs KTX-경부 목록(6번 "천안아산")이 각각 자기 이름으로 나오면서 서로 환승 배지를 주고받는 것을 확인했다.

### (2) 부역명 존치 역의 부역명 검색 허용

- **배경**: `src/lib/displayName.ts`의 `SUB_NAME_DISPLAY_EXCEPTIONS`(김천(구미)·울산(통도사)·쌍용(나사렛대)·총신대입구(이수))는 화면 표시 규칙일 뿐이었고, 검색 색인은 여전히 모든 역의 부역명을 통째로 제외하고 있었다 — "구미"·"통도사"·"나사렛대"·"이수"로는 못 찾았다.
- **수정**: `SUB_NAME_DISPLAY_EXCEPTIONS`를 `src/lib/displayName.ts`에서 export해 `run-import.ts`가 그대로 가져다 쓰게 했다(표시 예외 목록과 검색 가능 여부를 한 곳에서 관리) — 이 목록에 있는 역만 `station_alias`에 `SUB_NAME` 타입으로 부역명을 추가로 저장한다. 그 외 역(예: "봉황(김해여객터미널)")은 기존대로 부역명만으로는 검색되지 않는다.
- **검증**: 단위 테스트(총신대입구(이수) 관련 기존 테스트 2건을 새 동작에 맞게 갱신)와 통합 테스트(김천(구미)·울산(통도사) 부역명 검색 2건 + 일반 역은 여전히 제외됨을 확인하는 1건)를 추가했다. e2e 테스트로 "구미"→김천(구미), "통도사"→울산(통도사) 검색을 확인했다.

## 확장 16: 지선(branch line) — 경춘선 망우선

사용자가 위키백과 경춘선 문서 캡처를 주며, 상봉에서 갈라지는 "망우선"(광운대~상봉, 본선과 다른 코드 체계)을 어떻게 표현할지 논의했다. 정리 끝에: (1) 지선이 그 자체로 충분히 긴 노선이면(예: KTX 동해선 전구간) 별도 line로 분리하고, (2) 짧은 지선(예: 망우선, 2개 역)은 별도 line_id는 만들되 "노선 선택" 목록에는 안 넣고 본선을 고르면 자동으로 패널이 하나 더 붙는 방식으로 하기로 확정했다(사용자 제공 UI 초안 PDF 기준).

- **버그 발견**: 국가철도공단 원본 자체가 광운대(코드 "119", 지선 소속)를 경춘선 본선과 같은 (운영기관,노선코드) 조합("KR|K2")으로 묶어놓고 있어서, `station_line.sequence` 자연정렬 시 접두문자 없는 "119"가 "K117"보다 앞으로 튀어나와 "이 노선의 역 보기"의 1번이 광운대로 나오는 실제 버그가 있었다("119" < "K117"의 문자열 비교 때문).
- **스키마**: `line.parent_line_id`(nullable, `line.line_id` 자기 참조) 추가 — 이 값이 있으면 지선이다. `LineDefinition`에 `parentLineCode?`를 추가해 import 시점에 `LN-{parentLineCode}`로 해석한다.
- **지선 재분류**: `nationalLineDefinitions.ts`에 `RECLASSIFIED_LINE_CODE_BY_SOURCE_RECORD_ID`(원본이 본선과 같은 코드로 묶어놓은 특정 레코드만 다른 line_code로 재분류 — 광운대(`KR-K2-119`) 하나만 `KR-MANGU`로) + `SEOUL_METRO_BRANCH_SYNTHETIC_ROWS`(원본에 아예 없는, 지선 쪽에서 본 합류역 — 상봉을 "망우선" 소속으로 하나 더 추가, 새 역이 아니라 이름·지역이 같아 기존 상봉에 자동 병합됨)를 추가했다. 둘 다 원본 CSV는 안 건드리고 `nationalRegionSource.ts`의 로더 단계에서만 처리한다.
- **역명 동기화 안 함**: 망우선의 `iconLabel`을 경춘선과 똑같이 "경춘"으로 맞췄다 — 1호선에서 광운대를 보면 배지가 "망우선"이 아니라 "경춘"으로 보인다(사용자 확인: "1호선에서 볼 때 광운대역은 (경춘) 배지가 보이면 돼"). 색상도 자기 색이 따로 없으면 본선 색을 그대로 물려받는다.
- **UI**: `deriveLines()`에 `deriveSelectableLines()`(parent_line_id가 있는 지선은 "노선 선택" 목록에서 뺀다)와 `deriveChildLines()`(특정 노선의 지선들을 가져온다)를 추가했다. `App.tsx`가 노선을 고르면 그 노선의 `LineStationsPanel`과 함께, 지선마다 하나씩 추가 패널을 세로로 이어 붙인다 — `LineStationsPanel` 자체는 손대지 않았다(이미 있는 컴포넌트를 지선에도 그대로 재사용).
- **검증**: 단위 테스트(`deriveLines` 계열 4건), 통합 테스트(경춘선 24개 역이 청량리부터 시작, 망우선 2개 역, 노선 선택 목록에서 망우선 제외, 1호선의 광운대는 "경춘" 배지·상봉은 "1호선" 배지 없음 확인 4건), e2e 테스트(경춘선 선택 시 두 패널이 함께 나오고 각각 올바른 역 목록을 보여주는지)를 추가했다. 브라우저로 재현해 사용자가 준 PDF 초안과 동일한 화면(경춘선 24개 역 패널 + 망우선 2개 역 패널)을 확인했다.

**다음 지선**: 2호선·5호선·8호선·경의중앙선의 지선은 아직 반영 전 — 사용자가 위키백과 캡처를 순서대로 제공하면 같은 방식(RECLASSIFIED_LINE_CODE_BY_SOURCE_RECORD_ID / SEOUL_METRO_BRANCH_SYNTHETIC_ROWS / parentLineCode)으로 이어서 반영할 예정.

**후속 수정(같은 날)**: 사용자가 스크린샷으로, 망우선 자기 목록의 상봉 행에 본선("경춘") 배지가 붙어 있는 걸 보여주며 "지선에 대해서는 환승역에 본선을 넣을 필요는 없어"라고 지적했다 — 지선이 본선과 만나는 건 당연한 사실이라 굳이 배지로 보여줄 필요가 없다는 뜻이다. `listStationsOnLine()`에서 지금 보는 노선이 지선이면(`parentLineId`가 있으면) 그 본선의 line_id만 환승 배지 계산에서 빼도록 고쳤다 — 반대 방향(본선 목록에서 지선 배지를 보여주는 것)은 그대로 유지한다(사용자가 원하는 대로 정보가 비대칭적으로 필요한 방향에만 빠진다). 단위 테스트 2건(지선 목록에서 본선 배지 제외/본선 목록에서는 지선 배지 유지), 통합 테스트 1건, e2e 배지 검증을 추가했다.

## 확장 18: 지선 두 번째 — 경의중앙선 경의1선

## 확장 21: 지선 환승 배지 제거 + 본선-지선 치환 + 분기 표시

3개 지선(망우선·경의1선·마천지선)을 다 만들고 나니, 사용자가 강동·가좌·상봉(망우선 케이스) 화면을 직접 확인하고 세 가지를 요청했다: (1) 본선-지선 사이 환승 배지를 아예 없애고, 전체적으로도 지선이 아니라 "1~9호선 등" 큰 노선 하나만 표기할 것. (2) 마천지선·경의1선 같은 지선 자체를 키워드로 검색할 필요는 없음(별도 작업 불필요, 그냥 확인). (3) 대신 본선 쪽에서 지선이 갈라지는 지점을 표시해주면 좋겠다 — 방식은 위임("그건 너의 판단", 위키 같은 구분선도 아이디어로 제시).

- **본선-지선 상호 배지 제거**: 확장 16~20에서는 "지선 목록에서만 본선 배지를 뺀다"(단방향)였는데, 이번엔 반대 방향도 뺐다 — 본선 목록에서도 자기 지선 배지를 안 보여준다. `listStationsOnLine()`에 `isSameLineFamily(a, b)`(자기 자신이거나 서로 부모-자식 관계인지) 헬퍼를 추가해 두 방향 모두 걸러낸다.
- **지선을 본선 정체성으로 치환**: 지선 소속 노선이 "환승 배지"나 "검색 결과 배지"로 나타날 상황이면(본선-지선 관계가 아닌 경우), 지선 자신이 아니라 그 부모(본선)의 `LineRecord`로 바꿔서 보여준다(`resolveDisplayLine()`) — 예: 1호선에서 광운대를 보면 "망우선"이 아니라 "경춘선" 배지, 3호선에서 오금을 보면 "마천지선"이 아니라 "5호선" 배지. `searchGrouped()`의 `group.lines`도 같은 원칙으로 치환하고, 중복 판정을 `station_line_id`가 아니라 치환된 `line_id` 기준으로 바꿔 본선·지선 레코드가 같이 있어도 배지가 하나로 합쳐지게 했다.
- **분기 표시(사용자 판단 위임)**: 원형 환승 배지(`LineIconBadge`)와는 다르게, 점선 테두리의 사각 태그("↳ 망우선")를 역명 바로 옆에 추가했다 — "환승"이 아니라 "여기서 갈라짐"이라는 걸 시각적으로 구분하기 위해서다. `LineStationEntry`에 `branchLines: LineRecord[]` 필드를 새로 추가해 담당한다(본선에서 지선이 갈라지는 역에서만 채워짐).
- **검증**: 단위 테스트 4건(본선 자기 목록에서 지선 배지 제외+branchLines 확인, 다른 노선에서 지선 소속 역을 보면 본선 이름으로 치환, searchGrouped 치환 2건), 기존 통합 테스트 4건을 새 동작에 맞게 갱신(광운대·가좌·강동·서울역 관련), e2e 테스트 2건 갱신(오금 배지가 "마천지선"이 아니라 "5호선", 경춘선 본선에서 상봉에 사각 태그 확인). 전체 203개 단위/통합 테스트 + 26개 e2e + tsc/oxlint/build/cargo check 모두 통과했고, 브라우저로 상봉의 "↳ 망우선" 태그와 "오금" 검색 시 "5" 배지(마천지선 아님)를 직접 확인했다.

**추가로 발견한 버그(확장 21 반영 직후)**: 사용자가 "서울역과 같이 지선에있는 역들은 검색이 안되네"라고 제보했다. 원인은 badge 로직이 아니라 검색 자체의 `lineId` 필터였다 — `evaluateAndSort()`가 "노선 선택"으로 좁힐 때 `record.line.lineId === lineId`만 검사해서, 서울역처럼 본선(경의중앙선) 레코드 자체가 아예 없고 지선(경의1선) 레코드만 있는 역은 본선을 선택한 채로는 절대 매칭될 수 없었다.
- **수정**: `evaluateAndSort()`의 스코프 필터를 `record.line.lineId === lineId || record.line.parentLineId === lineId`로 넓혔다 — 본선을 고르면 그 지선 소속 레코드도 함께 검색 대상에 포함시킨다. "이 노선의 역 보기"가 지선을 본선 패널 아래 별도로 보여주는 것과 같은 원칙(지선은 본선 선택 범위에 포함된 것으로 취급)이며, `searchGrouped()`는 그대로 `resolveDisplayLine()`을 거쳐 배지를 "경의중앙선"으로 올바르게 치환해 보여준다.
- **검증**: 단위 테스트 1건(`search()`에 lineId로 본선을 지정해도 본선 레코드가 없는 지선 전용 역이 매칭됨을 확인) 추가, e2e 테스트 1건(경의중앙선 선택 후 "서울역" 검색 확인)을 기존 지선 테스트에 추가. 전체 204개 단위/통합 테스트 + 26개 e2e + tsc/oxlint/build 모두 통과했고, 브라우저로 경의중앙선 선택 상태에서 "서울역" 검색이 정상적으로 나오는 것을 재현·확인했다.

## 확장 22: 지선 키워드 검색 제거 + 노선 번호 키워드의 지역별 재정비

사용자가 두 가지를 요청했다: (1) "역명 검색 시 필터링 되는 노선 명 키워드는 본선명 즉 parents 명만 검색하는걸로. 마천지선 또는 경의1선과 같은걸로는 필터링 되지 않게." (2) 수도권 1~9호선은 숫자 그대로, 그 외 노선(경춘·경의·수인분당 등)은 기존 iconLabel과 같은 짧은 한글 키워드로, 비수도권 숫자 노선(인천·부산·대구·광주·대전 각 N호선)은 지역 접두 키워드(인1·부1~4·대구1~3·광1·대전1)로, 부산김해경전철은 BGL, GTX-A는 그대로(소문자 포함) 검색되게 해달라 — "이를 진행하는 이유는 1만 입력해도 인천, 부산, 대구, 광주 다 뜨기 때문이야." 진행 중 사용자가 "전체 검색시에 이와 같은 키워드 구분이 진행되는 것이지, 운행 범위를 부산으로 지정 시, 1만 적어도 부산 1호선이 검색되어야 한다"고 명확히 했다.

- **지선 키워드 제거**: `matchTextToken()`이 지선(`parentLineId`가 있는) 레코드를 검사할 때 지선 자신의 `normalizedName`/`aliases`가 아니라, 새 `lineById` 파라미터로 넘겨받은 **본선**의 것만 별칭 검사에 쓰게 했다. 하위 호환을 위해 `lineById`를 안 넘기면(기존 호출부·테스트) 기존처럼 자기 자신으로 대체한다. `evaluateAndSort()`가 매 검색마다 `candidates`로 `lineById` 맵을 만들어 넘긴다.
- **지역 충돌 확인(AskUserQuestion)**: 사용자가 처음 준 표는 "대구1~3 > 대1~3"과 "대전 1호선 > 대1"이 똑같이 "대1"로 겹쳤다 — 지역을 구분하자는 기능의 목적과 정반대라 바로 반영하지 않고 확인을 구했다. 사용자 답: "대구, 대전일 경우, 그냥 풀 네임 적는것으로 진행." → 대구는 "대구1"~"대구3", 대전은 "대전1"로 정했다.
- **노선 번호 토큰의 동적 모호성 판정**: `lineNumber` 필드 자체는 안 건드렸다(그대로 두면 부산처럼 범위를 이미 좁힌 경우 접두어 없는 숫자가 자연히 정확하게 동작한다). 대신 `evaluateAndSort()`가 검색마다 후보군(`scoped`) 안에서 같은 번호를 가진 서로 다른 노선이 몇 개인지 센다 — 2개 이상(예: "서울·수도권" 범위엔 인천 1호선이 같은 지역코드로 늘 같이 있고, "전체" 범위는 5개 지역이 다 겹친다)이면, 접두어 없는 숫자는 `isCanonicalNumberedLine()`(표시명이 정확히 "N호선"인, 즉 지역 이름이 안 붙은 노선)만 통과시키고 나머지는 실패시킨다. 후보군에 그 번호의 노선이 하나뿐이면(예: 부산 범위로 좁힌 상태) 평소처럼 숫자만으로 통과된다 — "부산으로 지정 시 1만 적어도 부산 1호선이 검색되어야 한다"를 정확히 만족한다.
- **지역 키워드 별칭 추가**: `nationalLineDefinitions.ts`에 인1·인2·부1~4·대구1~3·광1·대전1·BGL·GTX-A를 각 노선의 `aliases`에 추가했다(경춘·경의·수인분당 등 한글 키워드는 이미 officialName 부분 문자열로 걸려서 손대지 않았다).
- **부수적으로 발견한 오타 유사일치(FUZZY_MATCH) 버그**: 새 지역 키워드를 추가하자 "대구1"이 대구 1호선뿐 아니라 대구 2·3호선, 대전 1호선, 심지어 KTX/SRT 동대구역까지 걸리는 게 발견됐다 — `isTypoSimilar()`가 3~4글자 문자열에 편집 거리 1까지 허용해서, "대구1"과 "대구도시철도2호선"의 부분 문자열("대구도" 등)이 서로 오타 유사일치로 잡혔다. 검색어에 숫자가 있으면 오타 유사일치를 아예 적용하지 않도록 고쳤다(숫자는 "1"과 "2"처럼 서로 다른 대상을 가리키는 정확한 식별자이지 오타가 아니다) — 기존 "경천철"(오타) 같은 비-숫자 오타 유사일치 테스트는 그대로 통과한다.
- **검증**: 단위 테스트 다수 추가(지선 키워드 제외/본선 키워드 통과, `matchTextToken`의 `lineById` 파라미터 동작, 노선 번호 지역 모호성 판정 3가지 시나리오), 실제 데이터 통합 테스트 다수 추가(전체/서울·수도권/부산·대구·광주 범위에서의 "1"·"인1"·"부1"·"대구1"·"대전1"·"BGL"·"GTX-A" 검증, "망우선"·"마천지선"·"경의1선" 키워드로 아무것도 안 나오는 것 확인), e2e 테스트 3건 추가. 전체 224개 단위/통합 테스트 + 29개 e2e + tsc/oxlint/build/cargo check 모두 통과했고, 브라우저로 "전체" 범위에서 "1"(수도권 1호선만) vs "인1"(인천 1호선만), "마천지선"(결과 없음)을 직접 재현·확인했다. `data/generated/korsub.sqlite3`와 `public/korsub-dataset.json`은 `pnpm db:import`로 다시 생성했다.

## 확장 23: 2호선 네 번째 지선(성수지선·신정지선) + 본선 고유명("을지로순환선")

사용자가 나무위키 "서울 지하철 2호선/역 목록" 문서를 주며 "2호선 raw 엑셀 역코드 수정 완료. 위키 참고하여 지선 작업 진행. 2호선은 본선 명 밝히는 것으로 진행 (을지로순환선)"이라고 요청했다. 2호선은 순환선(을지로순환선, 시청~시청) 본선에 성수지선(성수~신설동)·신정지선(신도림~까치산) 두 지선이 갈라지는 구조다.

- **raw 변경 확인(diff)**: `data/normalized/*.csv`를 재생성해 이전 스냅샷과 비교하니, 사용자가 언급한 2호선 외에 두 가지가 더 바뀌어 있었다 — (1) 3호선 서울교통공사 구간(지축~오금, 34개 역) 코드가 309~342에서 319~352로 통째로 +10 이동해, 코레일(일산선, 대화~삼송) 구간과 겹치던 309~318 코드 중복이 해소됨. (2) 4호선 "불암산(당고개)"의 부역명이 사라지고 "불암산"으로만 남음. 둘 다 2호선과 무관하고 사전에 언급되지 않아 AskUserQuestion으로 확인했고, 둘 다 "의도한 것 맞음"으로 확정됐다.
- **3호선 override 정리**: 코드 중복이 해소되면서 `data/overrides/station-line-sequence.csv`에 있던 3호선 일산선 구간(KR-3-309~318) 정렬 전용 키 10건이 더 이상 필요 없어져 삭제했다(자연정렬만으로 이미 정확한 순서가 나온다) — 1호선(150~159, 아직 중복 남아 있음)·경의1선·경의중앙선 관련 override는 그대로 뒀다. `pnpm db:validate`의 "같은 노선 내 외부 코드 중복" 경고에서 3호선 항목이 사라지고 1호선 5건만 남은 것으로 확인했다.
- **성수지선·신정지선 반영**: 사용자가 원본 엑셀에 나무위키 역번 그대로 하이픈 확장 코드(성수지선 211-1~211-4, 신정지선 234-1~234-4)를 이미 붙여놔서, `RECLASSIFIED_LINE_CODE_BY_SOURCE_RECORD_ID`로 이 8개 레코드만 새 line_code(`SM-2-SEONGSU`/`SM-2-SINJEONG`)에 매핑하면 됐다 — 별도 정렬 키 없이 자연정렬만으로 성수/신도림(합류역) 바로 뒤에 정확히 이어진다. 합류역(성수 211, 신도림 234)은 이미 본선 레코드로 존재하지만 "지선이 여기서 갈라진다"는 사실 자체를 나타낼 지선 소속 레코드가 원본에 없어, 망우선·경의1선·마천지선 때와 같은 원칙으로 `SEOUL_METRO_BRANCH_SYNTHETIC_ROWS`에 합성 레코드 2건을 추가했다.
- **2호선 본선의 고유 명칭("을지로순환선")**: 5호선·경춘선과 달리, 2호선이라는 이름은 순환선+두 지선을 다 아우르는 상위 개념이라 본선 자체를 구분해 밝히기로 했다(사용자 확인). `displayName`을 "2호선"에서 "을지로순환선"으로 바꾸고, 키워드 검색용으로 `aliases: ['을지로순환선', '을지로']`를 추가했다 — `iconLabel`("2")과 `lineNumber`(2)는 그대로 둬서 배지·숫자 검색은 기존과 동일하게 동작한다.
  - **부수 버그 수정**: `isCanonicalNumberedLine()`(확장22에서 만든, "접두어 없는 순수 N호선"인지 판정하는 함수)이 `displayName`이 정확히 "N호선"인지를 정규식으로 검사하고 있었는데, 2호선의 displayName이 "을지로순환선"으로 바뀌면서 더 이상 매칭되지 않게 됐다 — 그대로 두면 "서울·수도권"·"전체" 범위에서 숫자 "2"를 검색할 때 아무 결과도 안 나오는 회귀가 생길 뻔했다. 판정 기준을 표시명이 아니라 구조적으로 안정적인 `operatorCode`("SM" 또는 9호선의 "S9")로 바꿔 고쳤다 — displayName이 앞으로 또 커스터마이즈돼도 흔들리지 않는다.
- **검증**: 단위 테스트(픽스처에 `operatorCode: 'SM'` 명시로 회귀 방지) + 통합 테스트 8건(을지로순환선 43개 역+지선 제외, displayName·iconLabel·lineNumber 확인, "을지로순환선"·"을지로" 키워드 검색, 성수지선·신정지선 각 5개 역 순서, "노선 선택" 제외/지선 목록 포함, 본선에서 성수·신도림의 분기 표시, 까치산의 진짜 5호선 환승 배지 유지, "성수지선"·"신정지선" 키워드로 아무것도 안 나옴) + e2e 테스트 갱신(2건, 을지로순환선 이름 반영 + 지선 패널 전체 흐름). 전체 231개 단위/통합 테스트 + 29개 e2e + tsc/oxlint/build/cargo check + `pnpm db:validate` 모두 통과했고, 브라우저로 을지로순환선 43개 역(성수에 "↳ 성수지선" 태그, 신도림에 "↳ 신정지선" 태그) + 두 지선 패널 + "을지로순환선" 키워드 검색을 직접 확인했다. `data/generated/korsub.sqlite3`와 `public/korsub-dataset.json`은 `pnpm db:import`로 다시 생성했다.

## 확장 24: 2호선 표시명 롤백 + stationListLabel 신설 + 1호선 2단계 지선(경부/장항선 → 경부고속선·병점기지선)

## 확장 25: 무궁화호 신규 지원 — group_name(노선 선택) × pattern_name(운행계통 토글)

사용자가 KTX와 같은 위치 구조(`data/raw/mugunghwa/{mugunghwa_patterns,mugunghwa_pattern_stops,mugunghwa_stations}.csv`)로 무궁화호 원본을 준비하고 요청했다: group_name으로 노선을 구분하고 pattern_name은 수도권 전철 지선처럼 토글로 보여주되(운행계통별 역을 그대로 확인할 수 있도록 pattern_stops 파일 순서대로, 중복 제거 없이), 검색 시에는 중복을 하나로 모으고 운행계통 사이엔 환승 배지를 붙이지 말 것. 노선 분류·아이콘은 참고 사이트(metrotyping.kr) "무궁화호" 화면을 그대로 따르고, "노선 선택" 토글에서 무궁화-장항선은 이전 KTX 방식(평면 노선)과 동일하게 하라고 정리했다. 이어진 "경부/장항선도 지선작업 하고 있는거지?" 질문에 대한 답으로 "구로~신창(경부선 구간)도 본선에서 분리해야 함" 게 아니라 이번엔 무궁화호 얘기였음이 확인됐고("경부/장항선이 구로<->신창 구간이야"는 확장24의 1호선 얘기), 무궁화호 자체는 raw 데이터(19개 pattern, 12개 group)를 그대로 반영했다.

- **KTX와의 구조적 차이**: KTX(`ktxGameLineSource.ts`)는 사용자가 이미 `game_line×origin_type`별로 역 목록을 평평하게 조인해 둔 파일 하나만 읽는다. 무궁화호는 그런 사전 조인 파일이 없어 — `mugunghwaSource.ts`가 `mugunghwa_pattern_stops.csv`(pattern_id·stop_order·station_id) × `mugunghwa_stations.csv`(station_id·station_name) × `mugunghwa_patterns.csv`(pattern_id·group_name·pattern_name)를 직접 조인한다. pattern_id 하나가 `mugunghwaDefinitions.ts`의 `LineDefinition` 하나에 1:1 대응한다(`rawLabel` = pattern_id).
- **group_name(12개) × pattern_name(19개) 매핑 규칙**: group에 pattern이 하나뿐이면(충북선·장항선·전라선·중앙선·태백선·영동선·경북선·교외선, 8개) KTX와 똑같이 그 group 자체가 평면 노선이다(사용자 확인: "노선 선택 토글에서는 무궁화-장항선의 이전 KTX와 동일한 방식으로"). group에 pattern이 여럿이면(경부선·호남선·동해선·경전선, 4개) patterns.csv에 먼저 나오는 pattern을 "대표"로 삼아 `displayName`을 group 이름(예: "무궁화-경부선")으로, `stationListLabel`(확장24 재사용)로 자기 pattern_name(예: "경부선(서울-제천)")을 밝힌다. 나머지 pattern은 `parentLineCode`로 대표에 딸린 자식 노선이 되어, `deriveDescendantLines()`(확장24)가 그대로 재사용돼 대표를 고르면 모든 계통 패널이 한꺼번에 펼쳐진다.
- **`suppress_branch_tag` 컬럼 신설**: 수도권 전철 지선과 달리 대표/자식 노선의 역 목록이 대부분 그대로 겹친다(예: "경부선(서울-제천)"·"경부선(서울-부산)"은 서울~조치원을 통째로 공유) — 사용자 확인: "중복에 대해서는 신경쓰지 말고 pattern-stops 파일의 순서대로 토글에 반영해줘". 그대로 두면 `listStationsOnLine()`의 "↳ 갈림" 분기 표시(원래 물리적 분기역 전용)가 겹치는 거의 모든 역에 붙어버린다 — 새 `line.suppress_branch_tag`(`LineDefinition.suppressBranchTag`) 컬럼을 자식 노선에 표시해 그 계산에서만 제외했다. 환승 배지 억제는 이 플래그와 무관하게 기존 `parentLineId` 관계만으로 이미 됐지만, **형제(같은 대표를 공유하는 자식끼리)** 사이는 안 됐다 — 3계통 그룹(호남선/동해선/경전선)은 대표가 아닌 두 자식끼리도 구간이 겹칠 수 있어(예: 호남선 "용산-목포"·"광주-목포"가 광주송정~목포를 공유), `isSameLineFamily()`를 부모-자식뿐 아니라 형제 관계까지 같은 계열로 보도록 일반화했다.
- **전용 pseudo-region("MUGUNGHWA")**: KTX/SRT와 같은 pseudo-region("KTX")을 쓰지 않고 새 region을 뒀다 — 무궁화호가 KTX/SRT나 도시 지역과 실제로 같은 역을 공유해도 확실하지 않은 한 자동으로 환승역 처리하고 싶지 않아서다(사용자 확인: "무궁화호 내 제외 타 지역별 환승역에 대해서 확실하지 않은 부분은 환승역이라고 우선 표기하지 말고"). 무궁화호 안에서(같은 region) 이름이 같은 역은 기존 자동/잠정 병합 규칙대로 계속 하나로 묶인다 — 이 덕에 검색 dedup(`searchGrouped()`의 `resolveDisplayLine` 치환)이 손 안 대고 그대로 재사용됐다: 겹치는 역의 대표/자식 레코드가 항상 같은 대표 line_id로 치환되어 배지가 하나만 남는다.
- **아이콘·색상**: 참고 사이트(metrotyping.kr) "무궁화호" 지역 선택의 "노선 선택" 배지를 브라우저로 열어 실제 `background-color`를 그대로 옮겼다(사용자 확인: "무궁화의 노선 구분은 사진과 같이 해주면 돼", "아이콘도 저 사진대로 진행해줘") — 배지 텍스트가 전부 "무궁화"라 `iconLabel`도 이 값으로 통일했다. 이 사이트에는 8개 그룹(장항선/영동선/태백선/호남선/충북선/경북선/경부선/교외선)만 있어, raw 데이터에 있는 전라선/중앙선/동해선/경전선 4개 그룹의 색은 AskUserQuestion으로 처리 방침을 확인한 뒤("같은 팔레트로 자동 선정") 같은 팔레트 계열(Chakra UI)로 임의 지정했다 — 공식 색상이 아니므로 `rail-line-colors-source.json`에 별도 표시해 뒀다.

## 확장 28: 무궁화호 토글 이름 괄호 제거 + KTX/SRT 브랜드 통합("착발" 구분)

사용자가 손그림 UI 목업(PDF)과 함께 두 가지를 요청했다: (1) 확장 27에서 만든 "(구간)" 토글 이름의 괄호를 빼고, (2) "KTX 노선 SRT 노선 병합... SRT 명도 KTX로 통합. 이때 노선 선택 안에서 동일한 노선명(예시 KTX-경부(행신착발) 와 KTX-경부(수서착발)) 이런 노선은 착발 구분으로 구분할 필요 있음. 착발 구분은 행신 착발 / 수서 착발으로."

- **괄호 제거**: `mugunghwaDefinitions.ts`의 대표(stationListLabel)·자식(displayName) 값에서 감싸던 괄호를 뺐다 — "(동대구-영주)" → "동대구-영주" 등, 정규식으로 10곳을 일괄 치환했다.
- **KTX/SRT 브랜드 통합**: `ktxGameLineDefinitions.ts`에서 옛 SRT(수서발) 5개 노선의 `displayName`·`iconLabel`을 전부 "KTX-" 접두어로 바꾸고 `trainServiceCode`도 "KTX"로 합쳤다 — 화면에 "SRT"라는 브랜드가 더 이상 보이지 않는다(run-import.ts에서 "SRT" scope_option/train_service row도 제거). 같은 이름이 겹치는 5개 계통(경부·호남·전라·경전·동해)만 "행신착발"/"수서착발" 접미어로 구분하고(괄호 없이 하이픈으로: "KTX-경부-행신착발"), 겹칠 상대가 없는 4개(강릉·중앙·동해[전구간]·중부내륙)는 접미어 없이 그대로 뒀다. SRT의 "동해"는 실제로는 옛 "KTX-동해"(확장 27에서 "KTX-경부-동해"로 개칭된 쪽, 경부선 경유 포항행)와 같은 계통이라 그 기준으로 접미어를 붙였다 — "KTX-동해"(전구간, 부전~강릉)와는 다른 계통이므로 착발 구분을 붙이지 않는다. `rawLabel`/`lineCode`/`operatorCode`(원본 조인 키·색상 매핑용)는 그대로 둬서 기존 override·색상이 전혀 깨지지 않는다.
- **검증**: `srtRecords`(테스트 헬퍼)를 `trainServiceCode==='SRT'`가 아니라 `operatorCode==='SRT'` 기준으로 바꾸고, KTX/SRT 관련 통합 테스트 전체(약 15건)와 아산/천안아산·운행범위·무궁화호 환승역 정리 테스트를 새 이름 체계에 맞춰 갱신했다. e2e도 "SRT" 범위 라디오를 없애고 KTX 범위 안에서 "행신착발"/"수서착발" 버튼으로 같은 시나리오를 재현하도록 6건을 다시 짰다. 전체 255개 단위/통합 테스트 + 31개 e2e + tsc/oxlint/build/cargo check + `pnpm db:validate` 모두 통과했고, 브라우저로 "KTX" 범위에서 SRT 버튼이 사라지고 "노선 선택"에 14개 노선(행신착발 5 + 수서착발 5 + 접미어 없는 4)이 정확한 이름·색으로 나오는 것을 직접 확인했다.

## 확장 29: 착발(행신/수서) 짝 시각적 그룹화

확장 28 직후 사용자가 "노선 구분 시 수서 및 행신 착발 노선에 대해서 그룹화 하는건 어때?"라고 제안했다. 먼저 "작업하지 말고 아이디어 브레인스토밍 해보자"는 요청에 따라 코드를 읽고 옵션을 정리했다 — `LineSelector.tsx`가 완전히 flat한 pill 목록이고, 무궁화 지선의 `parentLineId`/`suppressBranchTag`도 실제로는 "노선 선택"에 그룹 UI를 만들어주지 않는다는(그 자식은 애초에 `deriveSelectableLines()`에서 제외되어 목록에 안 뜨고, 본선을 고르면 패널로만 추가된다) 걸 확인한 뒤, 데이터 모델을 전혀 안 건드리는 프론트 전용 옵션(A: sortOrder만 짝끼리 인접하게 정렬, B: 짝을 하나의 캡슐 버튼으로 시각적으로 묶기)을 제안했고 사용자가 "A + B"를 골랐다.

- **A. sortOrder 재배열**: `ktxGameLineDefinitions.ts`의 배열 순서를 "KTX 9개 먼저 → SRT 5개 나중"(500번대/600번대)에서 "같은 계통의 행신착발 바로 다음에 수서착발"이 오도록(500~513 연속) 다시 짰다. 겹칠 상대가 없는 4개(강릉·중앙·동해[전구간]·중부내륙)는 원래 순서 그대로 그 사이에 남았다. `rawLabel`/`lineCode`/`operatorCode`·색상 매핑은 손대지 않았다.
- **B. 착발 캡슐 그룹**: `LineSelector.tsx`에 `displayName`이 "...-행신착발"/"...-수서착발"로 끝나는 두 노선이 모두 있으면(정규식으로 접미어를 떼어 "base" 문자열이 같은지 비교) 하나의 캡슐(테두리 하나로 둘러싼 그룹)로 묶어 그리는 로직을 추가했다 — 왼쪽엔 "KTX-경부" 같은 base 이름표, 오른쪽엔 "행신착발"/"수서착발" 반쪽 버튼 두 개가 구분선 하나만 두고 붙는다. 각 반쪽은 자기 노선의 실제 `colorHex`(예: KTX-경부 파랑 `#1F5AA6` vs SRT-경부 보라 `#5B2C83`)를 그대로 유지하고, 접근성 이름(`aria-label`)은 기존 `displayName` 전체("KTX-경부-행신착발")를 그대로 남겨 검색 결과 배지 등 다른 화면과 이름이 어긋나지 않게 했다. 짝이 없는 노선(강릉·중앙·동해·중부내륙, 그리고 무궁화호·지하철 등 다른 모든 노선)은 기존과 동일한 단독 pill로 렌더링된다 — 데이터 모델(`LineRecord`)·엔진(`engine.ts`)·override·색상 파일은 전혀 안 건드린 순수 표시 계층 변경이다.
- **검증**: 기존 255개 단위/통합 테스트(불변 — `LineSelector.test.tsx`는 착발 접미어가 없는 픽스처만 써서 캡슐 로직이 아예 발동하지 않는 flat 경로만 검증) 그대로 통과, 재수입(`db:import`) 후 `db:validate` 통과(override ID 변경이 전혀 없어 첫 시도에 바로 성공), tsc/oxlint 클린, 31개 e2e 전부 통과 — Playwright의 `getByRole('button', {name: 'KTX-경부-행신착발', exact: true})` 같은 기존 매처가 `aria-label` 덕에 캡슐 안에서도 그대로 맞아떨어졌다. 브라우저로 "KTX" 범위에서 5개 캡슐("KTX-경부"·"KTX-호남"·"KTX-전라"·"KTX-경부-동해"·"KTX-경전", 각각 행신착발/수서착발 반쪽 포함)과 4개 단독 pill이 정확한 순서·색으로 나오는 것, 캡슐 안에서 수서착발을 눌렀을 때 그 반쪽만 보라색으로 바뀌고 그룹 테두리가 파란색(선택 표시)으로 바뀌며 아래 패널이 "KTX-경부-수서착발" 15개 역으로 정확히 전환되는 것을 직접 확인했다.

**추가 개선(같은 세션)**: 캡슐을 실제로 본 사용자가 스크린샷 두 장과 함께 네 가지를 더 요청했다 — "KTX 노선 재정렬 필요성. 가독성이 좋지 않음", "사진처럼 토글이 된 색상에 맞춰서 테두리 색 동기화", "단일 노선과 동일하게, 색상 알이 미토글 상태에도 존재하게, 단 착발 별 색상이 다르므로, 원 하나를 반반으로 나누어서 착발 별 색상이 존재하게", "대구 1~3호선의 경우 네모난 알 내에 흰 숫자로 변경(이미지 참고)".

- **재정렬**: 1차 정렬("행신착발 바로 다음에 수서착발", 캡슐과 단독 pill이 목록 여기저기 불규칙하게 섞임)이 오히려 안 읽혔다는 지적에 따라, 착발 짝이 있는 5개(경부·호남·전라·경부-동해·경전, 캡슐)를 전부 앞으로, 짝이 없는 4개(강릉·중앙·동해·중부내륙, 단독 pill)를 전부 뒤로 몰아 목록이 "캡슐 구간 → 단독 구간" 두 덩어리로 나뉘도록 `ktxGameLineDefinitions.ts`의 sortOrder를 다시 짰다.
- **테두리 색 동기화**: `DeparturePointGroup`(`LineSelector.tsx`)의 선택 테두리를 고정된 `border-blue-600`에서, 지금 선택된 착발의 실제 `colorHex`를 그대로 쓰도록(`style={{borderColor: selectedLine.colorHex}}`) 바꿨다 — 단독 pill이 선택되면 자기 색으로 꽉 차는 것과 같은 원리를 캡슐에도 맞췄다.
- **착발별 반반 색상 점**: 캡슐의 base 이름표("KTX-경부" 등) 앞에, 단독 pill의 색상 점과 같은 크기(`h-2.5 w-2.5 rounded-full`)의 점을 추가했다 — 다만 착발 두 색이 다르므로 `linear-gradient(90deg, 행신색 50%, 수서색 50%)`로 원 하나를 정확히 반으로 갈라 각 절반에 각자의 색을 준다.
- **대구 1~3호선 사각형 배지**: 참고 이미지(빨간 사각형 안 흰 숫자)에 맞춰, `LineIconBadge`(환승 배지·자동완성 배지에 쓰는 24px 아이콘)가 `lineCode`가 "DT-1"/"DT-2"/"DT-3"일 때만 원(`rounded-full`) 대신 사각형(`rounded-md`)으로 그리도록 바꿨다 — 대경선(번호 없는 노선)과 다른 도시의 1~3호선(서울·부산·광주 등)은 요청 범위 밖이라 원형을 유지한다. 배지 내용(`iconLabel`, "대1"/"대2"/"대3")과 흰 글자색은 이미 기존과 동일해 바꿀 게 없었다 — 모양만 바뀐다.

## 확장 30: 무궁화호 노선명 "무궁화-" 접두어 제거

사용자가 "무궁화호에서는 노선에 '무궁화-'가 필요없네. 단일 노선 시 토글 박스에서도 '00선'만 보이게"라고 요청했다 — 무궁화호는 전용 region("MUGUNGHWA") 안에서만 노출되는 범위라 다른 범위와의 구분에 접두어가 실질적으로 필요 없었고, 원형 아이콘(iconLabel="무궁화")이 이미 그 역할을 하고 있었다.

- **13개 group_name 중 12개에서 "무궁화-" 제거**: `mugunghwaDefinitions.ts`의 displayName을 "무궁화-충북선" → "충북선" 등으로 바꿨다. 단일 계통(평면) 노선은 stationListLabel이 없어 토글박스가 displayName을 그대로 쓰므로, 이 변경만으로 "단일 노선 시 토글박스에서도 'OO선'만" 요청도 함께 충족됐다. 다중 계통 그룹(충북선·호남선·경전선)의 대표는 토글박스에서 여전히 자기 구간(예: "동대구-영주")을 보여준다 — "노선 선택" 버튼의 displayName만 바뀌었다.
- **동해선 예외 발견**: 재수입 후 DB를 직접 조회해, 부산 광역전철에 이미 별개의 "동해선"(`KR-DONGHAE`)이 있고 기장·남창·부전·센텀·신해운대·태화강 6개 역에서 두 "동해선"이 실제로 같은 역을 공유(이미 병합됨)한다는 걸 확인했다 — 접두어를 떼면 이 역들의 검색 결과에 이름이 완전히 같은 배지가 색만 다른 채로 두 개 뜨는 충돌이 생긴다. 사용자에게 처리 방향을 물으려 했으나 질문 도중 세션이 끊겨, 제시했던 추천안(동해선만 "무궁화-동해선" 예외 유지)으로 직접 진행했다 — 나머지 12개 그룹과 부산 광역전철 "동해선"·KTX 등 다른 모든 노선명은 그대로 두는 가장 안전한 선택지였다.
- **검증**: 재수입 → `db:validate` 통과. 단위/통합 테스트(무궁화호 group_name 목록·동해선 그룹 테스트 등)와 e2e(부전역 환승 배지 exact 매칭) 갱신 — 255개 단위/통합 + 31개 e2e 전부 통과, tsc/oxlint/build/cargo check 통과. 브라우저로 "무궁화호" 범위에서 12개 버튼이 접두어 없이("충북선" 등), "무궁화-동해선"만 예외로 나오는 것과, "부전" 검색 결과에 "동해선"(부산 광역전철)·"무궁화-동해선" 두 배지가 이름으로 정확히 구분되는 것을 직접 확인했다.

## 확장 32: ITX-청춘 추가

사용자가 "ITX 청춘 데이터 추가 완료 / 기존 수도권 경춘선을 공용으로 사용하는 노선임 / 구분 색은 역시 이전에 제공한 이미지의 색을 활용 / 뭔가 경전선이랑 색이 비슷한 것 같은데, 차별점 필요해보임"이라고 요청했다. 원본은 `data/raw/itx_cheongchun/{cheongchun_stations,itx_cheongchun_pattern_stops}.csv` — 계통 IC01 하나(용산→춘천 15개 역), patterns.csv는 없다.

- **로더/정의**: `itxCheongchunSource.ts`·`itxCheongchunDefinitions.ts`(patterns.csv가 없어 노선 정의가 그 자리를 대신). 계통이 하나라 group/토글 없는 평면 노선 `ITX-청춘`(`lineCode` ITX-CHEONGCHUN, 아이콘 "청춘"), `sourceRecordId`는 `ITXC-IC01-<station_id>`.
- **region = 서울·수도권("SEOUL_METRO")**: 경춘선의 선로·역을 공용하므로 별도 pseudo-region 없이 경춘선과 같은 region에 두었다 — 같은 region+같은 역명 자동 병합만으로 15개 역이 전부 기존 역과 하나로 합쳐진다(경춘선 12개 역, 그리고 용산·옥수·왕십리·청량리는 1호선·경의중앙선·2·3·5호선·수인분당선·KTX·무궁화호 환승 그룹에 합류; 별도 override 없음). 화면의 ITX 범위 구분은 `line.train_service_code="ITX"`다.
- **App.tsx 범위 필터 보정**: 도시 지역 범위(서울·수도권 등)는 `line.regionCode`만 보고 걸렀기 때문에 같은 region을 쓰는 ITX-청춘이 "서울·수도권" 노선 선택에 섞여 들어오게 된다 — 지역 범위에서는 `trainServiceCode`가 있는 노선을 빼도록 고쳤다(다른 지역 범위는 원래 그런 노선이 없어 영향 없음). 테스트 헬퍼 `seoulRecords`도 같은 기준으로 맞췄다.
- **ITX 범위**: `scope_option`의 ITX는 새마을(region "MUGUNGHWA")과 청춘(region "SEOUL_METRO")이 서로 다른 region을 써 하나로 묶을 수 없어 `region_code`를 비웠다(필터는 원래도 train_service_code). 노선 선택 순서는 게임 화면대로 ITX-청춘(sortOrder 790)이 맨 앞, 새마을 4개(800번대)가 뒤따른다.
- **색상 — 경전선과의 구분**: 게임 화면의 ITX-청춘 아이콘 색(`#1AA4C8`)은 ITX-새마을-경전(`#009BCD`)과 거의 같은 청록이라 헷갈린다는 지적이 맞아, 같은 이전 이미지 중 Railmap 전국 노선도의 **경춘선 색(초록 `#34A944`)**을 썼다. 새마을 5개 노선 색과의 RGB 거리가 모두 80 이상임을 테스트로 고정했다. 참고: 수도권 경춘선 배지(`#0C8E72`, 위키백과)와는 같은 초록 계열이라, 한 역에서 나란히 뜰 때는 아이콘 글자("청춘"/"경춘")로 구분된다 — 더 벌리고 싶으면 색만 바꾸면 된다.
- **검증**: 재수입(1832→1847행) + `db:validate` 통과, 단위/통합 261개(ITX-청춘 4건·범위 순서 1건 신설) + e2e 35개(서울·수도권 범위 미노출+경춘선 배지 공존, ITX-청춘 15개 역 2건 신설) + tsc/oxlint 통과.
