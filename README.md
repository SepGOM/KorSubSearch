# 대한민국 역명 통합 검색

전국 지하철·전철·광역철도의 역명을 노선까지 포함해 하나로 통합 검색하는 **데스크톱 전용** 프로그램입니다. 인터넷 연결 없이 동작합니다.

- 화면·문서: 한국어 / 코드 식별자: 영어
- 지원 범위: **서울·수도권 / 부산 / 대구 / 광주 / 대전 / KTX / 무궁화호** (ITX는 아직 데이터가 없어 "추후 지원"으로 화면에 노출만 됩니다) — SRT는 2026-09-16(2차)부터 별도 범위가 아니라 KTX 안의 "행신착발"/"수서착발" 이름 구분으로 통합됐습니다.
- 범위 + 노선을 고르면 "이 노선의 역 보기" 버튼으로 그 노선 전체 역을 물리적 순서대로(원본 STIN_CD 또는 KTX/SRT 원본의 "순번"/"stop_order" 자연 정렬 기준) 볼 수 있고, 환승역은 갈아탈 수 있는 다른 노선 배지가 함께 표시됩니다 — **지금 고른 범위 밖의 노선(예: KTX 범위에서 봐도 지하철·SRT 환승)까지 포함**합니다(사용자 확인). 검색 자동완성의 노선 배지도 마찬가지로 항상 범위 밖 환승까지 보여줍니다 — 예를 들어 SRT 범위에서 "오송"을 검색해도 그 역이 실제로 공용하는 KTX 5개 노선 배지가 함께 나옵니다.
- KTX/SRT처럼 지역이 아니라 전국을 가로지르는 열차 종류도 지역과 같은 방식으로 지원합니다 — 서울역·부산역처럼 기존 지하철·전철역과 같은 역사를 공용하는 역은 자동으로 환승역 배지가 붙습니다. KTX와 SRT는 2026-09-01부로 회사 차원에서는 같은 브랜드로 통합됐지만, 이 앱은 "수서발"(SRT)과 "서울/용산발"(KTX)을 사용자가 구분해 볼 수 있도록 별도 버튼으로 유지합니다.

## 데이터 파이프라인

```text
data/raw/운영기관_역사_코드정보_*.xlsx (전국 역사고유번호 원본, 1,102행)
  → 1단계 지역 분류: split-national-source.ts → data/normalized/{seoul-metro,busan,daegu,gwangju,daejeon}-stations.csv
  → 2단계 지역별 로더: nationalRegionSource.ts → 정규화(src/lib/normalize, "역" 접미사·괄호 부역명·가운데점/마침표 처리)
  → 동명역 후보 그룹핑(같은 지역끼리만 + 사람이 확인한 MERGE는 이름이 달라도 강제 병합)
  → 자동/잠정 병합 판정 → SQLite(schema.sql) + 검수 리포트 + 정적 JSON
```

원본은 `RAIL_OPR_ISTT_CD`(운영기관코드)/`LN_CD`(노선코드)/`STIN_CD`(역사코드)로 이루어진 전국 표준 코드 테이블 하나이며, 서울·수도권/부산/대구/광주/대전 5개 지역 전 노선을 담고 있습니다. 같은 실제 노선이 구간별로 운영기관이 갈리는 경우(예: 1호선 = 서울교통공사+한국철도공사, 4호선 = +남양주도시공사, 8호선 = +구리도시공사, 7호선 = +인천교통공사, 서해선 = 한국철도공사+서해철도)는 사용자 확인에 따라 하나의 노선으로 합칩니다 — 매핑표는 `scripts/import/sources/nationalLineDefinitions.ts`의 `OPERATOR_LINE_TO_CODE`에 있습니다. 인천국제공항 자기부상철도(6개 역)는 사용자 확인에 따라 제외했습니다.

| 지역 | 행 수 | 비고 |
|---|---|---|
| 서울·수도권 | 800 | |
| 부산 | 158 | |
| 대구 | 102 | 대경선(대구-경북 통근열차) 포함 |
| 광주 | 20 | 이번 버전에서 신규 지원 |
| 대전 | 22 | 이번 버전에서 신규 지원 |

이 원본에도 **좌표가 없어** 규칙 7.2의 자동 병합 조건(좌표 500m 이내 또는 공식 환승 확인)을 기계적으로 만족시킬 수 없습니다. "같은 지역 안에서 정규화 역명이 같으면 잠정 병합하고 검수 리포트에 남긴다"는 정책으로 처리했습니다 — 서로 다른 지역(예: 서울의 "중앙"과 부산의 "중앙")은 애초에 병합 후보로 보지 않습니다. `data/generated/station-resolution-review.csv`에 254건이 기록되어 있으며, 실제 좌표/공식 환승 자료가 확보되면 `data/overrides/station-resolution.csv`에 `MERGE`/`KEEP_SEPARATE`로 확정하면 됩니다.

이름이 서로 달라(동명이 아니어서) 자동으로는 절대 후보에 오르지 않는 환승역도 있습니다 — 예: 4호선·7호선이 공용하는 역은 원본에 이미 "총신대입구(이수)"로 통합 표기되어 있어 이름 기준 자동 그룹핑으로 합쳐지고, `data/overrides/station-resolution.csv`에 `MERGE`로 명시해 병합 근거를 "공식 환승 확인(OFFICIAL_TRANSFER)"으로 격상했습니다. 이름이 아예 다른 경우(원본에 아직 통합 표기가 없는 역)에는 `MERGE`만으로 정규화 역명이 달라도 강제 병합되고, 표시명을 바꾸고 싶으면 `data/overrides/station-display-name.csv`에 지정하면 됩니다.

**병합 = 이름 통일이 아닙니다.** 병합된 역도 `station.official_name`(대표 이름, 검색용)은 하나지만, `station_line.display_station_name`(화면 표시용, 노선별)은 기본적으로 각 노선이 원래 부르던 자기 이름을 그대로 유지합니다 — 실제로 정식 명칭이 서로 다른 환승역(예: 수도권 1호선 "아산역" ↔ KTX/SRT "천안아산역", 4호선 "총신대입구(이수)역" ↔ 7호선 "이수(총신대입구)역")이 병합됐다고 한쪽 이름으로 뭉개지지 않게 하기 위해서입니다(사용자 확인: "역명은 동기화하지 말고 환승 정보만 공유"). `station-display-name.csv`로 그룹 전체를 사람이 명시적으로 통일하기로 확정한 역(울산(통도사) 등)만 예외로 노선마다 같은 이름을 씁니다. 대표 이름이 아닌 쪽 원래 이름은 검색도 되도록 `station_alias`(MISC)에 자동으로 남습니다 — 이 김에 이름이 바뀐 역(예: 용인중앙시장역, 예전 "운동장.송담대")도 옛 이름으로 찾을 수 있게 됐습니다.

괄호 안 부역명(예: "봉황(김해여객터미널)")은 `station.sub_name` 필드에는 저장되어 화면에 그대로 표시되지만, 검색 색인(별칭)에는 기본적으로 넣지 않아 그 이름만으로는 검색되지 않습니다(사용자 확인). 단, 화면에서 부역명까지 남기기로 정한 역(김천(구미)·울산(통도사)·쌍용(나사렛대)·총신대입구(이수)·이수(총신대입구) — `src/lib/displayName.ts`의 `SUB_NAME_DISPLAY_EXCEPTIONS`)은 예외로 그 부역명만으로도 검색됩니다(사용자 확인: "부역명을 존치하기로 한 역은 그 부역명으로도 검색되게 하자") — 이 허용목록 하나를 import 스크립트와 화면 표시 로직이 함께 가져다 써서 "표시 여부"와 "검색 가능 여부"가 늘 같이 간다. "총신대입구(이수)"·"이수(총신대입구)"는 같은 역을 4호선·7호선이 서로 다른 순서로 표기하는 경우라 둘 다 목록에 넣어야 어느 노선에서 보든 괄호가 안 잘린다.

새 지역/출처를 추가하려면 `scripts/import/sources/`에 로더 하나만 추가하고 `run-import.ts`의 `SOURCE_LOADERS` 배열에 등록하면 됩니다 — 나머지 파이프라인(정규화, 그룹핑, DB 생성, 검증)은 출처 개수와 무관하게 동작합니다.

### KTX/SRT (별도 출처, 별도 pseudo-region, 운행계통 기반)

`data/raw/ktx-game-lines/game_line_stations.csv`(207행, `scripts/import/sources/ktxGameLineSource.ts`)를 두 번째 출처로 씁니다. 2026-09-07에 처음 KTX를 추가할 때는 "노선명+순번"만 있는 단순 평면 CSV(현재 `data/raw/_archive/`에 보관)를 썼는데, 그 원본은 실제 운행계통을 정확히 반영하지 못했습니다(예: "경부선"에 포항 지선이 섞여 있었음). 2026-09-08에 사용자가 실제 운행계통(패턴) 기준으로 다시 가공한 파일 5종(`stations.csv`, `patterns.csv`, `pattern_stops.csv`, `game_line_patterns.csv`, `game_line_stations.csv`, 전부 `data/raw/ktx-game-lines/`에 보관)으로 완전히 교체했습니다 — 파이프라인은 이미 조인·계산이 끝난 `game_line_stations.csv` 하나만 읽고, 나머지 4개는 그 산출 근거 자료로만 둡니다.

이 원본은 `game_line`(노선 버튼, 9개: 경부선/호남선/전라선/강릉선/중앙선/동해선/동해선 전구간/경전선/중부내륙선)과 `origin_type`(출발 계열: KTX=서울·용산발, SRT=수서발)을 함께 키로 씁니다. **2026-09-01부로 SRT가 KTX 브랜드에 통합돼 회사 차원의 "SRT"는 이제 없지만(사용자 확인), 이 앱은 사용자가 "수서발"과 "서울/용산발"을 구분해 검색할 수 있어야 해서 두 버튼을 계속 나눕니다.**

> **2026-09-16(2차) 갱신(확장 28)**: 위 문단은 첫 KTX 작업(2026-09-08) 당시의 설계다. 이후 사용자가 손그림 UI 목업과 함께 "KTX 노선 SRT 노선 병합... SRT 명도 KTX로 통합"이라고 다시 요청해, 화면에서 "SRT" 브랜드와 별도 범위 버튼을 완전히 없앴다 — `train_service_code`도 옛 SRT 5개 노선까지 전부 "KTX"로 합쳤다(`scope_option`에 "SRT" 행 자체가 없다). 대신 이름이 겹치는 5개 계통(경부·호남·전라·경전·동해)만 "행신착발"/"수서착발" 접미어로 구분한다(예: "KTX-경부-행신착발"/"KTX-경부-수서착발", 괄호 없이 하이픈으로 — 사용자 확인: "괄호는 빼줘"). `rawLabel`/`lineCode`/`operatorCode`(원본 조인 키·색상 매핑용)는 그대로 둬서 아래 설명된 region/병합 메커니즘 자체는 안 바뀌었다.

### 지선(branch line)

경춘선의 "망우선"처럼 짧게 갈라졌다가 본선에 다시 합류하는 지선은 `line.parent_line_id`(자기 참조)로 표현합니다. 지선은 **"노선 선택" 버튼 목록에는 나오지 않고**, 본선을 고르면 본선의 "이 노선의 역 보기" 패널 아래에 지선용 패널이 자동으로 하나 더 붙습니다(`deriveSelectableLines()`/`deriveChildLines()`, `App.tsx`) — `LineStationsPanel` 컴포넌트 자체는 그대로 재사용합니다.

- **지선이 그 자체로 충분히 긴 노선이면**(예: KTX 동해선 전구간) 완전히 별도의 `line`으로 분리하고, **짧은 지선**(예: 망우선, 2개 역)은 이 `parent_line_id` 방식을 씁니다 — 사용자 확인.
- **원본에 이미 있던 버그**: 국가철도공단 원본이 지선 역(광운대, 코드 "119")을 본선(경춘, 코드 "K11x~P14x")과 같은 (운영기관,노선코드) 조합으로 묶어놓아서, 자연정렬 시 "119"가 "K117"보다 앞으로 튀어나와 "이 노선의 역 보기"의 1번이 광운대로 나오는 실제 버그가 있었습니다. `nationalLineDefinitions.ts`의 `RECLASSIFIED_LINE_CODE_BY_SOURCE_RECORD_ID`로 그 레코드 하나만 지선 소속으로 재분류해 고쳤습니다(원본 CSV는 그대로 둡니다).
- **원본에 아예 없던 합류역**: 지선이 본선과 만나는 역(상봉)은 원본에 지선 소속 레코드가 없어서, `SEOUL_METRO_BRANCH_SYNTHETIC_ROWS`에 합성 레코드를 하나 추가했습니다 — 새 역이 아니라 이름·지역이 같아 기존 상봉에 자동으로 병합됩니다.
- **역명은 동기화하지 않되, 배지에선 본선 이름으로 보임**: 지선의 `icon_label`을 본선과 똑같이 맞춰서(망우선의 iconLabel="경춘"), 1호선처럼 지선과 만나는 다른 노선에서는 배지가 "망우선"이 아니라 "경춘"으로 보입니다(사용자 확인). 색상도 지선 전용 색이 없으면 본선 색을 그대로 물려받습니다.
- **본선-지선 사이엔 환승 배지를 아예 안 보여줌**: 강동·가좌·상봉처럼 본선-지선이 만나는 역이라도, 서로를 "환승 배지"로 표시하지 않습니다(사용자 확인: "지선간 분리되는 부분에 있어서 환승 알을 표기할 필요 없어") — `listStationsOnLine()`의 `isSameLineFamily()`가 자기 자신이거나 부모-자식 관계인 노선을 양방향으로 걸러냅니다.
- **지선은 배지에서 항상 본선 이름으로 치환됨**: 지선 소속 역이 다른 노선(본선-지선 관계가 아닌)의 환승 배지나 검색 결과로 나타날 때는, 지선 자신이 아니라 그 본선의 이름·색으로 보여줍니다(사용자 확인: "전체 노선에서도... 큰 노선(1~9호선 등등)만 하나만 표기") — 예: 3호선에서 오금을 보면 "마천지선"이 아니라 "5호선" 배지가 붙습니다. `resolveDisplayLine()`이 담당하며, `searchGrouped()`의 배지 목록도 같은 노선(치환 후 line_id 기준)이면 하나로 합칩니다.
- **분기 표시**: 배지를 없앤 대신, 지선이 갈라지는 역의 이름 옆에 점선 사각 태그("↳ 망우선")를 붙여 "환승"이 아니라 "여기서 갈라짐"이라는 걸 원형 배지와 시각적으로 구분합니다(`LineStationEntry.branchLines`) — 방식은 사용자가 판단을 맡겨 위키 스타일 구분선 대신 이 태그로 정했습니다.
- **두 번째 사례 — 경의중앙선의 경의1선**: 가좌에서 갈라져 신촌·서울역으로 이어지는 구간을 같은 방식으로 분리했습니다. 나무위키 문서의 "용문홍천선"(용문역 제외 전부 가칭, 미개통)은 사용자 확인에 따라 분리하지 않았고, 애초에 원본 정부 데이터에도 없습니다.
- **세 번째 사례 — 5호선의 마천지선**: 강동에서 갈라져 둔촌동~마천으로 이어지는 구간입니다. 이번엔 사용자가 원본 엑셀에 이미 P54x 접두 코드로 지선 역을 재분류해 둔 상태로 요청이 와서, `RECLASSIFIED_LINE_CODE_BY_SOURCE_RECORD_ID`로 그 코드를 새 line_code에 매핑하기만 하면 됐습니다 — 서쪽 김포·검단 연장(가칭 정거장 다수, 확정 역명도 원본에 아직 없음)은 손대지 않았습니다.
- **네 번째 사례 — 2호선의 성수지선·신정지선**: 성수에서 갈라져 신설동으로, 신도림에서 갈라져 까치산으로 이어지는 두 지선입니다. 사용자가 원본 엑셀에 나무위키 역번 그대로 하이픈 확장 코드(211-1~211-4, 234-1~234-4)를 붙여놔서, 재분류만으로 별도 정렬 키 없이 자연정렬로 정확한 순서가 나왔습니다.
  - **본선의 "이 노선의 역 보기" 전용 이름(`station_list_label`)**: 5호선·경춘선의 본선은 그냥 "5호선"·"경춘선"으로 불러도 되지만, 2호선은 "2호선"이라는 이름이 순환선(을지로순환선)+두 지선을 다 아우르는 상위 개념이라 본선을 구분해 밝히고 싶다는 요청이 있었습니다. 처음엔 `displayName` 자체를 "을지로순환선"으로 바꿨는데, 그러면 "노선 선택" 버튼까지 바뀌어 버려 사용자가 "이거는 바꾸라고 얘기 안했는데;; 다시 2호선으로 롤백"이라고 정정했습니다 — "밑에 리스트를 변경해달라는거였지, 위의 노선 명을 바꾸라곤 안했어". 그래서 `displayName`(노선 선택 버튼·환승 배지 등 대부분의 자리)은 그대로 "2호선"으로 두고, `LineStationsPanel`(이 노선의 역 보기)에서만 쓰는 새 필드 `station_list_label`("을지로순환선(본선)")을 따로 만들었습니다 — 없으면 그 패널도 displayName을 그대로 씁니다. 키워드 검색용 별칭("을지로순환선"·"을지로")도 `aliases`에 추가했습니다.
  - **부수 효과**: 노선 번호 지역 모호성 판정(`isCanonicalNumberedLine()`, 위 "노선 번호 키워드와 지역 모호성" 절 참고)이 원래 `displayName`이 정확히 "N호선"인지로 판정했는데, displayName이 앞으로 커스터마이즈될 수 있다는 게 드러나면서 더 안정적인 `operatorCode`(서울교통공사 "SM" 또는 9호선 "S9") 기준으로 바꿨습니다.
- **다섯 번째 사례 — 1호선의 경부/장항선(2단계 지선)**: 1호선은 본선(경원선·종로선·경인선, 소요산~구로~인천)에 "경부/장항선"이라는 큰 지선(구로~신창, 실제로는 경부선 구간이며 신창 이후 비전철 장항선으로 이어짐)이 하나 더 붙고, 그 경부/장항선 안에서 다시 금천구청→광명(경부고속선 연결선, "광명 셔틀")·병점→서동탄(병점기지선)이 갈라지는 **지선의 지선(2단계 계층)**입니다(사용자 확인: "경부/장항선이 구로<->신창 구간이야"). `parentLineCode`를 본선이 아니라 "경부/장항선"으로 지정해 처음으로 2단계 부모-자식 관계를 만들었습니다 — `resolveDisplayLine()`은 원래도 "바로 위 한 단계"만 보므로 그대로 맞았지만(광명은 다른 곳에서 "경부/장항선"으로, 경부/장항선 소속 역은 "1호선"으로 각각 한 단계씩만 치환됩니다), "본선을 고르면 하위 지선 패널이 전부 나온다"는 화면 동작은 직계 자식만 보는 기존 `deriveChildLines()`로는 손자뻘 지선이 안 나와서, 몇 단계든 재귀적으로 모으는 `deriveDescendantLines()`를 새로 만들어 `App.tsx`가 쓰도록 바꿨습니다. 노선 색 상속(`findLineColor` 폴백)도 바로 위 부모까지만 보던 걸, 색을 찾을 때까지 조상을 계속 거슬러 올라가도록 고쳤습니다.
  - **부수 버그(아산/천안아산 회귀)**: 아산이 1호선(sortOrder=1, 항상 KTX보다 낮음)에서 경부/장항선(sortOrder=1204, KTX의 500대보다 높음)으로 옮겨가면서, "아산" 검색 시 대표 이름이 "천안아산"으로 뒤바뀌는 회귀가 생겼습니다. 알고 보니 두 레코드는 station 레벨 공유 이름("아산")으로 항상 동점이었고, 그 동점을 갈라온 진짜 이유는 의도한 동점 해소 로직(`ownNameMatchesAliasToken`)이 아니라 우연한 `line.sortOrder` 순서였습니다 — 그 해소 로직은 ALIAS_MATCH 필드에서만 작동했는데 이 경우엔 STATION_EXACT라 애초에 작동을 안 했던 겁니다. 필드 종류와 무관하게 "자기 이름과 정확히 같은지"(부분 포함이 아니라 완전 일치 — "아산"이 "천안아산"의 부분 문자열이라 포함 검사로는 여전히 동점이 남)를 보도록 일반화(`ownNameMatchesToken`)해 근본적으로 고쳤습니다.
- **여섯 번째 사례 — 무궁화호의 group_name × pattern_name(운행계통 토글)**: 물리적으로 갈라지는 지선이 아니라, 같은 노선을 서로 다른 운행계통(예: 경부선의 "서울-제천"↔"서울-부산")이 대부분 겹치는 구간으로 지나가는 경우입니다. group에 계통이 여럿이면(경부선·호남선·동해선·경전선) 먼저 나오는 계통을 대표로 삼아 `displayName`을 group 이름(예: "무궁화-경부선")으로, `station_list_label`로 자기 계통명을 밝히고, 나머지 계통은 `parentLineCode`로 대표에 딸린 자식이 되어 `deriveDescendantLines()`(다섯 번째 사례에서 만든 함수)를 그대로 재사용해 한 화면에 토글로 펼쳐집니다. 다만 지선과 달리 대표/자식의 역 목록이 대부분 그대로 겹쳐서(사용자 확인: "중복에 대해서는 신경쓰지 말고 pattern-stops 파일의 순서대로 토글에 반영해줘"), 새 `suppress_branch_tag` 플래그로 자식 노선에서만 "↳ 갈림" 분기 표시를 끄고, `isSameLineFamily()`를 부모-자식뿐 아니라 **형제(같은 대표를 공유하는 자식끼리)**까지 같은 계열로 보도록 일반화해 3계통 그룹(호남선 등)에서 형제끼리 환승 배지가 잘못 붙는 걸 막았습니다. 검색 시 겹치는 역이 배지 하나로 합쳐지는 건 기존 `resolveDisplayLine()` 치환 로직이 손 안 대고 그대로 처리합니다. 또한 무궁화호는 KTX/SRT와 같은 pseudo-region을 쓰지 않고 전용 region("MUGUNGHWA")을 둬서, 실제로 같은 역을 공유해도 확실하지 않은 타 지역 환승은 자동으로 만들지 않습니다(사용자 확인: "무궁화호 내 제외 타 지역별 환승역에 대해서 확실하지 않은 부분은 환승역이라고 우선 표기하지 말고"). 노선 분류·아이콘·색상은 참고 사이트(metrotyping.kr) "무궁화호" 화면을 그대로 따랐고, 그 사이트에 없는 4개 그룹(전라선·중앙선·동해선·경전선) 색만 같은 팔레트 계열로 임의 지정했습니다(공식 색 아님, 사용자 확인).
- **본선 자체의 순서 보정도 필요할 수 있음**: 경의중앙선 본선은 원본 코드가 세 구간(용산선 K1xx, 경원선·중앙선 K1xx+청량리·왕십리만 K2xx, 경의선 K3xx)으로 나뉘어 있어 자연정렬로는 도라산~지평의 실제 순서가 전혀 안 나왔습니다 — 56개 역 전부 `data/overrides/station-line-sequence.csv`에 나무위키 km 순서 기준 정렬 전용 키를 매겨 바로잡았습니다(1호선·3호선의 운영기관 중복 코드 보정과 같은 방식). 도라산은 나무위키 캡처에 없었지만 임진강 바로 위(북쪽) 역이라는 사용자 확인에 따라 맨 앞에 뒀습니다.
- **지선 자신의 이름은 검색 키워드로 안 먹힘**: "망우선"·"마천지선"·"경의1선"처럼 지선 자신의 공식명·별칭으로는 아무 것도 안 나옵니다 — `matchTextToken()`이 `parentLineId`가 있는 레코드는 지선 자신이 아니라 본선(parent) 쪽 `normalizedName`·`aliases`로만 노선 키워드를 매칭합니다(사용자 확인: "필터링 되는 노선 명 키워드는 본선명 즉 parents 명만 검색"). 본선명("경춘"·"경의"·"5")으로는 지선 소속 역도 그대로 찾을 수 있습니다.

### 노선 번호 키워드와 지역 모호성

숫자만 입력해도(예: "1") 원래는 서울 1호선뿐 아니라 인천·부산·대구·광주·대전의 "1호선"까지 전부 걸렸습니다(전부 `line.lineNumber===1`). 사용자 확인에 따라 다음 규칙으로 정리했습니다.

- **접두어 없는 순수 숫자("1"~"9")는 "N호선"(지역 이름이 안 붙은 노선, 즉 수도권 1~9호선)만** 가리킵니다. 인천·부산·대구·광주·대전처럼 이름에 지역이 붙는 노선은 전용 키워드로만 찾습니다: 인1·인2, 부1~4, 대구1~3, 광1, 대전1(대구·대전은 둘 다 "대"로 시작해 줄임말이 겹치므로 사용자 확인에 따라 대전만 풀 네임을 씀), 부산김해경전철은 BGL, GTX-A는 그대로(대소문자 무관).
- 이 구분은 **후보군 안에 같은 번호를 가진 노선이 실제로 여러 개 있을 때만** 적용됩니다(`evaluateAndSort()`가 매 검색마다 동적으로 판정) — 운행 범위를 이미 부산 하나로 좁혔다면(후보군에 그 번호의 노선이 하나뿐이면) 접두어 없이 "1"만 입력해도 부산 1호선이 정상적으로 나옵니다(사용자 확인: "운행 범위를 부산으로 지정 시, 1만 적어도 부산 1호선이 검색되어야 한다"). "서울·수도권" 범위는 인천 노선과 지역코드를 공유해서 늘 이 판정이 걸립니다.
- **오타 유사일치(FUZZY_MATCH)는 검색어에 숫자가 섞이면 적용하지 않습니다** — "대구1"·"대전1"처럼 3글자 키워드는 편집 거리 1 허용 폭 때문에 "대구2호선"·"대전1호선"의 부분 문자열과 서로 뒤섞여, 이 키워드를 만든 목적(지역 구분)과 정반대가 됩니다.

## 노선 색상 출처 및 라이선스

`data/reference/rail-line-colors.csv`(54행)는 두 출처를 합친 것입니다(`data/reference/rail-line-colors-source.json`에 출처별로 기록).

1. [위키백과 "틀:한국 철도 노선색"](https://ko.wikipedia.org/wiki/틀:한국_철도_노선색) (2026-09-07 확인, oldid 41271877) — 서울·수도권 24개 + 부산 6개 + 대구 4개(1~3호선, 대경선) + 광주 1개 + 대전 1개, 총 40행. 문서의 서술이나 지시문은 요구사항으로 취급하지 않았습니다. 위키백과 텍스트는 CC BY-SA 4.0이며, 색상값 자체는 사실 정보로 간주해 사용했습니다.
2. [metrotyping.kr](https://metrotyping.kr)의 KTX/SRT 노선 선택 화면 — KTX 노선 9개(경부/호남/전라/강릉/중앙/동해/동해 전구간/경전/중부내륙) + SRT 노선 5개(경부/호남/전라/동해/경전), 총 14행. 사용자가 지정한 참고 사이트이며 코레일 공식 색상 규정은 아닙니다(사용자 확인에 따라 참고 자료로 사용). 이 사이트는 SRT 호남선을 목포행/광주송정행 두 배지로 더 세분하는데, 우리 데이터는 하나로 합쳤습니다.

앱은 이 CSV를 로컬에서만 읽으며, 실행 중에는 어떤 외부 페이지도 호출하지 않습니다.

## 알려진 한계 (이번 버전)

- ITX(열차 종류별 정차역): 데이터 없음 — 화면에 "추후 지원"으로만 노출. KTX/SRT/무궁화호는 실제 데이터가 들어와 지원됩니다.
- "동해선 전구간"은 KTX 쪽에 서울~동대구 구간(패턴 P05)이 빠져 있고(부전~강릉 구간만 반영) SRT 쪽은 데이터 자체가 없습니다 — 원본 결함이며, 사용자 확인에 따라 임의로 보정하지 않고 원본 그대로 둡니다.
- 좌표 데이터 없음 — 자동 병합이 대부분 "잠정(NAME_ONLY_PROVISIONAL)" 상태이며 사람 검수가 필요.
- 전국 통합 원본에는 영문 역명·주소·환승역여부 컬럼이 없어, 이전 부산 원본에 있던 영문 별칭은 이번 재가져오기에서 빠졌다(사용자 확인).
- 전철역코드 "4.19민주묘지역"은 최초 가져오기 때 인코딩이 깨져 "4?19민주묘지역"으로 들어왔던 걸 사용자가 공식 표기(마침표)로 확인해 줘 정정했다(`scripts/import/run-import.ts`의 `stripEncodingArtifacts`). 검색 시에는 마침표를 넣지 않아도("419민주묘지") 찾을 수 있다.
- 대경선은 부산·울산에 걸친 동해선과 마찬가지로 실제로는 대구·경북(경산 등)에 걸쳐 있으나, 아직 별도 "경북" 범위가 없어 잠정적으로 "대구"에 포함.
- `StationService`/좌표 관련 필드는 스키마와 로직은 준비되어 있으나 이번 원본 데이터에는 채울 값이 없음. 괄호 안 부역명은 `station.sub_name`에 항상 저장되지만, 검색 색인(별칭)에는 넣지 않아 부역명만으로는 검색되지 않는다(사용자 확인). 화면 표시에서도 대부분 부역명을 떼지만("봉황(김해여객터미널)역" → "봉황"), "쌍용(나사렛대)"·"총신대입구(이수)"·"김천(구미)"·"울산(통도사)"는 예외로 부역명까지 유지한다(`src/lib/displayName.ts`의 허용목록, 사용자 확인). 김천(구미)은 원본(`game_line_stations.csv`)에 이미 정식 표기로 들어 있고, 울산(통도사)은 원본은 "울산" 그대로 두고 `data/overrides/station-display-name.csv`(`GL-경부선-KTX-S063`)로만 표시명을 얹었다.
- 화면 표시에서는 "역" 접미사를 떼지만("방학역" → "방학"), "서울역"·"부산역"·"대구역"·"동대구역"·"대전역"·"서대구역"은 예외로 접미사를 유지한다(`src/lib/displayName.ts`의 허용목록). 검색·정규화 자체는 영향받지 않는다.
- 부산 1호선·동해선의 "좌천"·"부전"은 이름은 같지만 실제로는 환승되지 않는 별개의 역이라 `data/overrides/station-resolution.csv`에 `KEEP_SEPARATE`로 명시했다(사용자 확인) — 동래역(1·4호선 환승, 동해선은 별개)과 같은 패턴이다.
- 용인 에버라인 "운동장.송담대"역은 "용인중앙시장"으로 역명이 바뀌어(사용자 확인) `data/overrides/station-display-name.csv`에 반영했다.
- 오타 유사일치(FUZZY_MATCH) 판정이 다섯 글자 안팎의 긴 역명에서는 편집 거리 허용치가 다소 느슨해, 실제로 무관한 역이 검색 결과 맨 아래쪽에 섞여 나올 수 있다(순위 자체는 항상 완전일치보다 낮다). 필요하면 `src/lib/normalize/fuzzy.ts`의 허용치를 조정한다.
- "경성대.부경대(동명대학교)역"처럼 가운데점·마침표로 두 역명을 이어붙인 표기는 비교용 문자열(`normalizeForCompare`)에서 그 문장부호를 완전히 뺀다 — 검색어에 문장부호를 넣지 않아도("경성대부경대") 찾을 수 있고, 초성 검색("ㄱㅅㄷㅂㄱㄷ")도 된다. 공식 원문 표시에는 영향 없다.
- 이전 버전에서 쓰던 서울·수도권/부산 개별 원본(CSV/xlsx)과 사용자가 추가한 대구 1~3호선 xlsx 3종은 전국 통합 원본으로 대체되어 더 이상 가져오기 파이프라인에서 쓰지 않는다 — 삭제하지 않고 `data/raw/_archive/`로 옮겨 보관한다(`data/metadata/sources.json`의 `superseded_sources`/`unused_files`에 기록).
- **"이 노선의 역 보기"의 순서(`station_line.sequence`)는 원본 STIN_CD를 노선(line_id) 단위로 자연 정렬한 값이다(사용자 확인).** 다만 1호선·3호선은 서로 다른 두 운영기관(예: 1호선의 한국철도공사 vs 서울교통공사)이 같은 코드 구간(1호선 150~159, 3호선 309~318)을 완전히 다른 두 구간에 각각 독립적으로 매겨, 자연 정렬만으로는 실제 순서를 복원할 수 없었다 — `data/overrides/station-line-sequence.csv`로 그 20개 역만 사람이 확인한 정렬 전용 키를 부여해 바로잡았다(원본 `source_station_code` 값 자체는 건드리지 않았고, `scripts/validate/run-validate.ts`의 "같은 노선 내 외부 코드 중복" 경고는 그 원본 결함 사실만 계속 알린다).
